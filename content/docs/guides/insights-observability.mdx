## Overview

Your workspace keeps track of trust scores and task state as work happens. Most of the time you ask for those explicitly with `spl trust`, `spl task list` or `spl status`. **`spl insights`** works the other way round. It lists what the workspace *already noticed*, so the things worth your attention come to you.

```bash
spl insights
```

```
Insights:
  ⚠ Trust drift: did:sync:agent:dev in 'code' — a shift in recent verdicts
    was detected after 302 observation(s); review recent reviews.
```

If nothing needs attention, `spl insights` says so.

## What it surfaces

Insights are worked out from your records. There are two kinds.

### Trust drift

[Trust](/docs/concepts/trust) watches each actor's reviews for a *change in pattern*, such as a run of acceptances that turns into a run of rejections, or the reverse. When the shift is significant, you get a drift signal naming the actor and domain.

A drift signal is a prompt to look, not a verdict. An agent whose recent work in `code` started getting rejected might be facing a kind of task it is weak at, working against a moved target, or running on a different model. The signal tells you *where* to look. The [trust page](/docs/concepts/trust) explains how scoring works.

### Lingering open work

Insights also flags threads and tasks that were opened and never closed, well past when you would expect. It is the same signal [task triage](/docs/guides/task-suggestions#spl-task-triage--find-what-to-close) uses. You can pick the work back up, reassign it or close it.

## When to run it

`spl insights` is quick and read-only. Run it whenever you want to see what is drifting:

- **At the start of a session**, alongside `spl status`, to see if anything moved while you were away.
- **After a burst of agent work**, to catch trust drift early.
- **Periodically**, the way you would check task triage, so stalled work and trust shifts do not pile up.

## How it relates to `spl status`

The two are complementary:

| Command | Answers | Character |
|---|---|---|
| `spl status` | "Is the system healthy right now?" | A snapshot: uptime, record and thread counts, recent activity, and the top task suggestions when available. |
| `spl insights` | "What has the system noticed that I should look at?" | A short list of observations: trust drift and lingering work. |

`spl status` is the dashboard and `spl insights` is the alert list. Run both at the start of a session: status for the health check, insights for what to watch.

Insights pairs naturally with [`spl task suggest`](/docs/guides/task-suggestions) — insights shows what is drifting, and suggest shows what to do about it.
