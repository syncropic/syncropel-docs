The Studio answers everyday questions without a terminal: did my automation
run, and if not, why; why did a run stop; how much have I used the assistants;
and is my workspace all right.

## An automation's runs

Open **automations**, then an automation. Under **Runs**, the newest runs come
first, each with its date and time and what happened:

| Label | What it means |
|---|---|
| **Ran** | It ran. |
| **Skipped** | The workspace wasn't running at that time, and the automation's schedule says to skip missed runs. |
| **Not needed** | Its condition wasn't met, so there was nothing to do. This isn't a problem. |
| **Didn't run** | It couldn't start. The reason follows. |
| **Didn't finish** | It started but stopped before it was done. |
| **Stopped** | Someone stopped it. |
| **Waiting** | It's waiting for an answer from someone. |

The reason after the label is in plain words, for example:

- "It wasn't allowed to start: it would have gone past a limit or rule set for it."
- "It couldn't start: the assistant it hands work to isn't available."
- "The model provider turned it down or didn't answer."
- "It needs a key that isn't set."

A reason never shows the information the automation was working on. If the
Studio doesn't have words for a reason yet, it says so and shows a short code you
can pass to support.

If there have been no runs, the list says **No runs yet.**

To change when an automation runs, see
[Scheduled triggers](/docs/guides/scheduled-triggers).

## How runs went

On **automations**, the owner sees **How runs went**: how every run in the
workspace ended, counted over the **Last 24 hours** and the **Last 7 days**. It
shows counts only, never a list of runs.

| Label | What it counts |
|---|---|
| **Finished** | Runs that did what they were asked. |
| **Stopped early** | Runs that reached the most steps one run can take. |
| **Ran out of budget** | Runs that reached their spending limit. |
| **Stopped, repeating itself** | Runs stopped because they kept making the same call. |
| **Couldn't do it** | Runs where the assistant said it couldn't do the work. |
| **Failed** | Runs that went wrong. |
| **Waiting on someone** | Runs waiting for an answer. |

If the workspace restarted during the week, the counts start from then, and the
section says so: "Counted since this workspace last started," and the date.

## Checks

Beside How runs went, **Checks** lists what the workspace's own checks found:
anything failing first, then notes, each in the workspace's own words. These are
the same checks `spl doctor` runs.

A run that didn't finish says why, in one line, and then shows what the assistant
wrote about what it had done.

- **It took the most steps it can.** "Stopped after 12 steps, the most one run
  can take." The number is the run's own.
- **It kept repeating itself.** "Stopped because it made the same … call three
  times and got the same answer each time." The call is named by the tool's name.
  If the run asked a question, the question follows.
- **One call kept failing.** "Stopped because one … call kept failing."
- **It couldn't do the work.** The assistant's own reason is shown.

In lists, a run's state reads **running**, **waiting on you**, **answered** (or
**finished** for a run that wasn't asked from a conversation), **stopped**,
**stopped early**, **stopped, repeating itself** or **couldn't do this**. A
conversation nobody has answered reads **unanswered** and how long, such as
"unanswered · 15 days".

### What a run cost

Where you can see a run's cost, it's shown as an amount. When the model's price
isn't known, it reads **Cost not known**, never $0.

### More about a run

A run's details can also say:

- "Spending limit: the standard one, because none was set." (the owner sees this);
- "A draft was kept.", with **See the draft**, when a run that ran out of budget
  had something ready;
- "Answered without making a plan first." and "Ran on" the model it ran on,
  when you've turned on Detail's "How a run is going".

## When an automation stops

When an automation needs you, it comes to your **inbox**. Opening it shows what
went wrong, when, and what you can do. It never opens on a blank page.

### It failed three times in a row

An automation that fails three times in a row stops until you resume it. Its row
reads "Library health · stopped after 3 failures in a row", and opening it says:

> Library health stopped after failing 3 times in a row.
> It last failed today at 8:00 AM.
> It won't run again until you resume it.

It also says what it spent today, and **What went wrong last time**, in the
automation's own words, or "No reason was recorded."

Choose **Resume it**, **Turn it off** or **Leave it stopped**. **See the
automation** and **See the last run** take you to each.

### A step keeps failing

When one step fails several times in a row, that step is skipped and the rest of
the automation keeps running. The row reads "Library health · a step is being
skipped", and opening it says, for example, "A step in Library health failed 3
times in a row, so it's being skipped." and when it's tried again. There's
nothing to resume; press **Got it**.

### Other reasons

- **Its daily budget.** "Library health reached its daily budget, so it won't run
  again until" a time.
- **The workspace's daily limit.** "This workspace reached its daily spending
  limit, so no automation runs until" a time. "The limit is changed with spl on a
  computer." Press **Got it**.
- **Its assistant isn't available.** "Library health can't run, because the
  assistant it's set to use isn't available here." Set it to another assistant,
  or **Turn it off**.
- **A step failed in one run.** "The step … in Library health failed, so this run
  stopped there." with **See the run**. "Next time it's due, it runs again."

For a reason the Studio has no words for yet, the page shows the workspace's own
sentence, a **Details** fold, links to what it's about, and **Got it**.

## Your usage

Open **You**. In the workspace's section, **Your usage** shows your own
assistant use only, never anyone else's:

- **Runs on your plan**: runs included with the workspace's plan, today and this
  month. These are never shown in dollars.
- **Runs on your own key**: runs that used a model key you added yourself.
- **Cost on your own key**: what those runs cost, estimated at your provider's
  prices.

**By assistant** splits the runs by assistant name. A row with nothing in it is
left out, and if you haven't used an assistant this month, the section says **No
assistant use yet this month.**

The columns read **Today** and **This month**. The workspace counts its days in
UTC, so the section says when today's counts reset, in your own time: "Today's
counts reset at" and a time.

## Health of a hosted workspace

On a hosted workspace you own, while you're signed in to your Syncropel account,
**This workspace** has a **Health** line. It shows the one thing that matters
most right now:

| Line | What it means |
|---|---|
| **Running fine** | Nothing needs you. |
| **Not responding since** a time | The workspace stopped answering. It restarts itself when this happens. |
| **Storage is full** / **Storage is almost full** | It's out of, or close to running out of, storage. |
| **Not saved off this machine since** a time | The copy kept off the machine isn't being updated. This isn't the daily backup. |
| **1 thing needs you**, or a count | Something is waiting for you. |
| **Asleep. Fine when it last answered** | The workspace is idle and was fine the last time it answered. |
| **No report yet** | There's nothing to show yet. |

If the line is more than 15 minutes old, it adds **last checked** and a time.
Press **See all ›** for every check in detail.

On a workspace you run yourself, the **Health** line comes from the workspace's
own checks instead.
