Policies in Syncropel define what a [namespace](/docs/concepts/namespaces) allows, denies, and budgets. They compose through the namespace hierarchy via monotonic narrowing: child policies can only restrict, never expand, what the parent allows.

## Setting a Policy

Policies are set per namespace using a JSON or YAML file:

```bash
spl policy set acme/analytics policy.json -j
```

### Policy File Format

```json
{
  "capability": {
    "primitives": ["GET", "CALL"],
    "shapes": ["ONE", "MANY", "OPTIONAL"],
    "operations": ["db.*", "llm.generate"],
    "resources": ["/sync/database/*"],
    "max_effects": 500,
    "max_depth": 25
  },
  "deny": {
    "rules": [
      {
        "resources": ["/secret/*"],
        "primitives": ["GET"]
      },
      {
        "operations": ["db.drop_*"],
        "primitives": ["CALL"]
      }
    ]
  },
  "budget": {
    "compute_usd": 0.05,
    "latency_ms": 30000,
    "quality_floor": 0.5,
    "risk_ceiling": 0.3
  },
  "dial_ceiling": 0.5
}
```

## Capability Envelope

The capability defines the **allowed effect space**:

| Field | Type | What It Controls | Empty Means |
|-------|------|-----------------|-------------|
| `primitives` | string array | Which primitives (GET, PUT, CALL, MAP) | All allowed |
| `shapes` | string array | Which shapes (VOID, ONE, OPTIONAL, MANY, KEYED) | All allowed |
| `operations` | string array | Glob patterns for operations | All allowed |
| `resources` | string array | Glob patterns for resources | All allowed |
| `max_effects` | integer | Maximum effects per trace | 1000 (default) |
| `max_depth` | integer | Maximum nesting depth | 50 (default) |

### Glob Patterns

Operations and resources use glob matching:

| Pattern | Matches | Doesn't Match |
|---------|---------|--------------|
| `*` | Everything | — |
| `db.*` | `db.query`, `db.scan`, `db.insert` | `llm.generate` |
| `db.query` | `db.query` only | `db.scan` |
| `/sync/database/*` | `/sync/database/users`, `/sync/database/orders` | `/sync/secret/key` |

## Deny Rules (Forbid-Wins)

Deny rules explicitly block effects. They follow **forbid-wins** semantics: any deny rule match at any namespace level blocks the effect, regardless of capability grants.

```json
{
  "deny": {
    "rules": [
      {
        "resources": ["/secret/*"],
        "primitives": ["GET"]
      }
    ]
  }
}
```

This blocks all GET effects on any resource matching `/secret/*`. No capability envelope at any child namespace can override this.

Deny rules are particularly useful for:
- **Protecting secrets**: Block all reads to `/secret/*` paths
- **Preventing destructive operations**: Block `db.drop_*`, `db.truncate_*`
- **Restricting specific principals**: Block certain operations from untrusted service accounts

## Budget Envelope

Budget constrains session cost across 4 dimensions:

| Field | Type | What It Caps | Zero Means |
|-------|------|-------------|-----------|
| `compute_usd` | decimal | Total compute cost in USD | Unlimited |
| `latency_ms` | decimal | Total latency in milliseconds | Unlimited |
| `quality_floor` | decimal \[0,1\] | Minimum output quality | No minimum |
| `risk_ceiling` | decimal \[0,1\] | Maximum risk score | No maximum |

Budget is tracked with Decimal precision — no floating-point drift. [Check 5](/docs/concepts/governance) validates session totals. [Check 8](/docs/concepts/governance) validates per-effect quality and risk bounds.

## Policy Composition

When the governance engine resolves a namespace, it walks the full hierarchy and composes policies at each level:

```
DEFAULT (all primitives, $0.10 budget, 0.5 dial)
  └── acme (all primitives, $0.10 budget, deny: /secret/*)
      └── acme/analytics (GET+CALL only, $0.05 budget)
          └── acme/analytics/prod ($0.02 budget, 0.3333 dial)
```

### Composition Rules

| Attribute | Rule | Example |
|-----------|------|---------|
| **Primitives** | Intersection | Parent \{GET,PUT,CALL,MAP\} ∩ Child \{GET,CALL\} = \{GET,CALL\} |
| **Shapes** | Intersection | Parent \{all\} ∩ Child \{ONE,MANY\} = \{ONE,MANY\} |
| **Operations** | Pattern subsumption | Parent `db.*` subsumes child `db.query` |
| **Resources** | Pattern subsumption | Parent `/sync/*` subsumes child `/sync/database/*` |
| **Max effects** | min() | min(1000, 500) = 500 |
| **Max depth** | min() | min(50, 25) = 25 |
| **Deny rules** | Union | Parent denies + child denies (accumulate) |
| **Budget** | Tighter bound | min per dimension |
| **Dial ceiling** | min() | min(0.5, 0.3333) = 0.3333 |

**Key principle**: A child namespace can never grant more than its parent. It can only restrict further.

## Viewing Policies

```bash
# Show the policy set on a specific namespace
spl policy show acme/analytics -j

# Show the effective (resolved) policy after hierarchy composition
spl namespace resolve acme/analytics/prod -j
```

The resolved view is what your [session permissions](/docs/concepts/governance) actually use — it's the final result after walking the entire ancestor chain.

## Testing Policies

Before setting a policy in production, test it:

```bash
# Test if a specific effect would be allowed
spl policy test acme/analytics \
  --primitive GET \
  --operation db.query \
  --resource /sync/database/users \
  --dial 0.4 -j
```

## Common Policy Patterns

### Read-Only Namespace

```json
{
  "capability": {
    "primitives": ["GET", "MAP"]
  }
}
```

Allows reading and transforming data, but no writes (PUT) or external calls (CALL).

### Restricted Production

```json
{
  "capability": {
    "primitives": ["GET", "CALL"],
    "operations": ["db.query", "llm.generate"],
    "max_effects": 100
  },
  "deny": {
    "rules": [
      {"operations": ["db.drop_*", "db.truncate_*"], "primitives": ["CALL"]},
      {"resources": ["/secret/*"], "primitives": ["GET"]}
    ]
  },
  "budget": {
    "compute_usd": 0.01,
    "latency_ms": 10000,
    "risk_ceiling": 0.2
  },
  "dial_ceiling": 0.3333
}
```

REPLAY-only, low budget, no destructive operations, no secret access.

### Development Sandbox

```json
{
  "capability": {
    "primitives": ["GET", "PUT", "CALL", "MAP"],
    "operations": ["*"],
    "resources": ["*"]
  },
  "budget": {
    "compute_usd": 1.00,
    "latency_ms": 300000
  },
  "dial_ceiling": 1.0
}
```

Wide open for experimentation. All primitives, all operations, generous budget, full dial range.
