`spl run` starts a run as you and stays with it: every turn prints as it
happens, a question the run needs answered is put to you right there, and the
outcome prints when the run ends, with the diff if it changed a repository.

```bash
spl run "Record one note saying the walkthrough works, then stop."
```

The full guide is [Running work with spl run](/docs/guides/spl-run). It covers:

- what a run is and which member carries it out,
- what each line of output means,
- what happens when a run pauses for a decision, and how you answer it,
- the outcome and its exit codes,
- how a run is limited (turns, budget, time, the tools it may use),
- giving a run a repository, and the passing check it then owes,
- what does and does not stop a run.

## The old goal path

`--legacy` runs the older way: the goal is filed as an intent, routed to
a member, and checked until something closes it. Use it only if you depend on that behavior. Otherwise use plain `spl run`.
