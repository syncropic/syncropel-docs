## Prerequisites

- `spl serve --daemon` running (port 9100)
- Director actor registered: `spl actor show director`
- Dev actor registered with CLI adapter: `spl adapter list`
- Director prompt file at `~/.syncro/director-prompt.md`

## Step 1: Register Director Adapter

```bash
spl adapter add did:sync:agent:director \
  --family cli \
  --binary claude \
  --timeout 600 \
  --max-concurrent 1
```

## Step 2: Create Event Triggers

### On task approval — Director picks the next task

```bash
spl config add-trigger \
  --name "director-on-approval" \
  --match "act=KNOW,body.topic=task_verdict,body.verdict=accept" \
  --target did:sync:agent:director \
  --goal "Read and follow ~/.syncro/director-prompt.md. A task was just approved. Run: spl memory list --actor did:sync:agent:director && spl task list && spl trust. Assess the board and dispatch the next highest-priority inbox task to dev." \
  --budget 2.0 \
  --timeout 600 \
  --cooldown 120 \
  --max-concurrent 1
```

### On task failure — Director handles it

```bash
spl config add-trigger \
  --name "director-on-failure" \
  --match "act=KNOW,body.fulfills=*,body.success=false" \
  --target did:sync:agent:director \
  --goal "Read and follow ~/.syncro/director-prompt.md. A task just failed. Run spl task list and identify the failed task. Read the failure reason. Decide: re-decompose, re-assign, or escalate to David." \
  --budget 1.0 \
  --timeout 300 \
  --cooldown 120 \
  --max-concurrent 1
```

### Periodic check — every 15 minutes

```bash
spl config add-trigger \
  --name "director-periodic" \
  --schedule "*/15 * * * *" \
  --target did:sync:agent:director \
  --goal "Read and follow ~/.syncro/director-prompt.md. Periodic check. Run: spl task list && spl trust. Check for: idle inbox tasks to dispatch, tasks in review to approve, stale active tasks. Act on what you find." \
  --budget 1.0 \
  --timeout 300
```

## Step 3: Verify

```bash
# List configured triggers
spl config list-triggers

# Check trigger status
spl status
```

## How It Works

Once configured, the Director loop is fully autonomous:

1. **Task approved** → Director wakes, reads state, dispatches next task
2. **Task failed** → Director wakes, reads failure, decides how to handle
3. **Every 15 min** → Director checks for stale work, idle agents

The loop emerges from the engine's existing 4-loop architecture — no separate process needed. Event triggers wire records to actors. The Director is just an actor that happens to manage other actors.

## Safety

| Mechanism | Setting | Purpose |
|---|---|---|
| Cooldown | 120s | Prevents burst-firing on rapid approvals |
| Max concurrent | 1 | One Director session at a time |
| Budget | $2/dispatch | Caps cost per Director wakeup |
| Circuit breaker | 3 failures → auto-disable | Prevents runaway on errors |
| Chain depth | 5 max | Prevents recursive trigger loops |

## Disabling

```bash
# Pause all Director triggers
spl config add-trigger --name "director-on-approval" --disable
spl config add-trigger --name "director-on-failure" --disable
spl config add-trigger --name "director-periodic" --disable

# Re-enable
spl config add-trigger --name "director-on-approval" --enable
```

## The Director Prompt

The Director's operating manual lives at `~/.syncro/director-prompt.md`. It defines:
- How to load state (memories, tasks, trust)
- The priority ladder (review → unblock → multipliers → inbox → create)
- Task creation patterns
- Escalation rules (when to ask the human)
- Quality gates for reviewing work

Edit this file to change the Director's behavior. No code changes needed.
