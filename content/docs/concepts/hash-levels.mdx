Syncropel uses **content-addressed hashing** to identify computational patterns at progressive levels of detail. Each level strips away more information, creating a privacy gradient: Exact reveals everything, Intent reveals only the data flow shapes. This hierarchy is the foundation of privacy-preserving federation — you share knowledge across organizations without revealing sensitive details.

These are **Frozen Foundations F6, F7, F8, F9, F10**.

## The Levels

| Level | Name | What's Hashed | Privacy | Shared? |
|-------|------|--------------|---------|---------|
| **L0** | Exact | Primitive + shapes + operation + parameters | Maximum detail | **Never** (F8) |
| **L1** | Structural | Primitive + shapes + operation | High | Yes |
| **L2** | Flow | Primitive + shapes | Medium | Yes |
| **L3** | Intent | Shapes only | Minimum detail | Yes (safest) |

Each level is a strict subset of the level below it. Stripping parameters gives L1. Stripping the operation gives L2. Stripping the primitive gives L3.

## Canonical JSON Format

Every hash is computed as SHA-256 over a canonical JSON string — keys sorted alphabetically, no whitespace, compact separators (F10, F14).

**L3 (Intent)** — shapes only:
```json
{"in":"ONE","out":"MANY"}
```

**L2 (Flow)** — add primitive:
```json
{"in":"ONE","out":"MANY","p":"GET"}
```

**L1 (Structural)** — add operation:
```json
{"in":"ONE","op":"db.query","out":"MANY","p":"GET"}
```

**L0 (Exact)** — add parameters (keys sorted):
```json
{"in":"ONE","op":"db.query","out":"MANY","p":"GET","params":{"limit":100,"table":"users"}}
```

The hash is always: `sha256(canonical_json) → 64-character lowercase hex`.

If no operation is specified, it defaults to the lowercase primitive: `GET → "get"`, `MAP → "map"` (F15).

## The Containment Property

**Frozen Foundation F9**: If two effects match at L0, they necessarily match at L1, L2, and L3. But the reverse is not true.

```
L0 match  ⟹  L1 match  ⟹  L2 match  ⟹  L3 match
L3 match  ⟹̸  L2 match  ⟹̸  L1 match  ⟹̸  L0 match
```

This means:
- Two effects with the same L3 hash have the same shape flow — but may use different primitives, operations, and parameters
- Two effects with the same L1 hash do the same thing structurally — but with different runtime values
- Two effects with the same L0 hash are identical in every way

## L0 Never Leaves

**Frozen Foundation F8**: L0 hashes must never leave the local namespace.

L0 includes parameters — database names, API keys, user IDs, model configurations. Sharing L0 would leak sensitive operational details. This rule is enforced structurally:

- Federation queries on L0 return 403 Forbidden
- Cross-namespace grants cannot include L0 in their `hash_levels`
- Consent edges only allow L1, L2, L3

Your L0 hashes are always accessible locally — you can see your own exact patterns. But they never cross a namespace boundary.

## Hash Access by Dial Zone

The [Dial](/docs/concepts/the-dial) zone controls which hash levels a session can access:

| Dial Zone | Hash Access | What You Can Match |
|-----------|------------|-------------------|
| REPLAY \[0, 1/3) | L0 | Exact patterns only |
| ADAPT \[1/3, 1/2) | L0, L1 | Structural patterns (different params, same operation) |
| EXPLORE \[1/2, 2/3) | L0, L1, L2 | Flow patterns (different operations, same primitive + shapes) |
| CREATE \[2/3, 1\] | L0, L1, L2, L3 | Intent patterns (different primitives, same shape flow) |

Higher autonomy unlocks coarser matching — discovering patterns you wouldn't find with exact search.

## Sequence Hashing

For a sequence of effects, individual hashes are joined with commas and hashed again:

```
sequence_hash = sha256(hash_effect1 + "," + hash_effect2 + "," + ... + "," + hash_effectN)
```

This applies at each level independently: you get L0, L1, L2, L3 hashes for the entire sequence.

## "One Donor Teaches All"

This is why the hash hierarchy matters for federation:

1. Alice runs `GET ONE→MANY db.query {"table":"customers"}` successfully
2. Her registry records observations at L1: `sha256({"in":"ONE","op":"db.query","out":"MANY","p":"GET"})`
3. Bob runs `GET ONE→MANY db.query {"table":"orders"}` — different parameters, same L1 hash
4. Bob's registry can fetch Alice's L1 observations: 47 successes, 2 failures, avg cost $0.003
5. Bob benefits from Alice's experience without seeing her parameters, her table names, or her data

No model sharing. No gradient exchange. No coordination protocol. Just hash-indexed observation tuples flowing through consent-gated channels.

## Using the Library

```python
from syncropel_registry_core.hashing import compute_hashes, hash_effect

# Hash a single effect at all 4 levels
effect = {
    "primitive": "GET",
    "input_shape": "ONE",
    "output_shape": "MANY",
    "operation": "db.query",
    "parameters": {"table": "users"},
}

hash_l0, hash_l1, hash_l2, hash_l3 = compute_hashes([effect])

# Or hash at a specific level
l2_hash = hash_effect(effect, level=2)

# Verify containment: same L2 regardless of parameters
effect_b = {**effect, "parameters": {"table": "orders"}}
assert hash_effect(effect, level=2) == hash_effect(effect_b, level=2)  # True
assert hash_effect(effect, level=0) != hash_effect(effect_b, level=0)  # True
```
