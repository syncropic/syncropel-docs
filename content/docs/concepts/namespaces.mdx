Namespaces are the **unit of everything** in Syncropel: governance scope, tenancy boundary, federation unit, secrets scope, and budget allocation. They form a 5-level hierarchy where governance monotonically narrows — a child namespace can never have more permissions, more budget, or more autonomy than its parent.

## The 5 Levels

| Level | Name | Example | Typical Use |
|-------|------|---------|-------------|
| 0 | **DEFAULT** | `default` | System-wide baseline (always exists) |
| 1 | **ORG** | `acme` | Organization boundary |
| 2 | **PROJECT** | `acme/analytics` | Project scope |
| 3 | **ENV** | `acme/analytics/prod` | Environment (prod/staging/dev) |
| 4 | **JOB** | `acme/analytics/prod/job-42` | Individual session |

Level is derived from the number of segments in the ID:
- `default` → DEFAULT
- 1 segment → ORG
- 2 segments → PROJECT
- 3 segments → ENV
- 4 segments → JOB

## Namespace IDs

IDs are slash-separated, lowercase, alphanumeric with hyphens and underscores:

```
^[a-z0-9][a-z0-9_-]*(/[a-z0-9][a-z0-9_-]*)*$
```

| Constraint | Limit |
|-----------|-------|
| Max total length | 256 characters |
| Max segment length | 63 characters |
| Max user segments | 4 (DEFAULT is implicit root) |

## Monotonic Narrowing

When resolving a namespace, the system walks from DEFAULT down to the target, composing governance at each level. The composition rules ensure capabilities can only narrow:

| Attribute | Composition Rule | Effect |
|-----------|-----------------|--------|
| **Capability (primitives, shapes)** | Set intersection | Child can only use primitives/shapes the parent allows |
| **Capability (operations, resources)** | Pattern intersection | Child operations must be subsumed by parent patterns |
| **Capability (max_effects, max_depth)** | min() | Child can't exceed parent's structural limits |
| **Deny rules** | Union | Child inherits all parent denials, plus adds its own |
| **Budget** | Restriction (tighter wins) | Child budget ≤ parent budget per dimension |
| **Dial ceiling** | min() | Child can't be more creative than parent allows |
| **Hash access** | Set intersection | Child can't access hash levels parent doesn't allow |

**Forbid-wins**: Any deny rule at any level in the chain blocks the effect. No amount of ALLOW at a child level can override a DENY from a parent.

## Resolution Example

```
DEFAULT
  capability: {GET, PUT, CALL, MAP}
  budget: compute=$0.10, latency=60s
  dial_ceiling: 0.5
  deny: []

  └── acme (ORG)
        capability: {GET, PUT, CALL, MAP}  (same — no restriction)
        budget: compute=$0.10              (inherited)
        dial_ceiling: 0.5                  (inherited)
        deny: [{resources: ["/secret/*"], primitives: ["GET"]}]

        └── acme/analytics (PROJECT)
              capability: {GET, CALL}       (narrowed — removed PUT, MAP)
              budget: compute=$0.05         (tightened)
              dial_ceiling: 0.5             (inherited)

              └── acme/analytics/prod (ENV)
                    capability: {GET, CALL} (inherited from project)
                    budget: compute=$0.02   (further tightened)
                    dial_ceiling: 0.3333    (restricted to REPLAY)
                    deny: [{resources: ["/secret/*"], primitives: ["GET"]}]
                                            (inherited from acme)
```

Effective policy at `acme/analytics/prod`:
- **Can do**: GET and CALL effects only
- **Budget**: $0.02 compute, 60s latency
- **Dial**: REPLAY zone only (ceiling 1/3)
- **Denied**: Any GET on `/secret/*` resources (from the acme-level deny rule)

## The DEFAULT Namespace

Every registry has a `default` namespace that serves as the root. It provides baseline governance:

| Attribute | Default Value |
|-----------|-------------|
| Primitives | GET, PUT, CALL, MAP (all four) |
| Shapes | VOID, ONE, OPTIONAL, MANY, KEYED (all five) |
| Operations | `["*"]` (all operations) |
| Resources | `["*"]` (all resources) |
| Max effects | 1000 |
| Max depth | 50 |
| Budget (compute) | $0.10 |
| Budget (latency) | 60,000 ms |
| Dial ceiling | 0.5 (ADAPT) |
| Deny rules | None |

These defaults are deliberately generous for development. Production namespaces should tighten them.

## Using the CLI

```bash
# Create a namespace hierarchy
spl namespace create acme -j
spl namespace create acme/analytics -j
spl namespace create acme/analytics/prod -j

# Set a restrictive policy at the project level
spl policy set acme/analytics --primitives GET,CALL -j

# See the effective (resolved) configuration
spl namespace resolve acme/analytics/prod -j

# Switch context (like kubectl use-context)
spl namespace use acme/analytics/prod
```

## Using the Library

The namespace resolver uses **callback injection** — you provide functions for fetching namespaces and policies from any backing store:

```python
from syncropel_registry_core.namespaces import resolve_namespace

# Your storage callbacks (works with DuckDB, PostgreSQL, in-memory, anything)
def get_ns(ns_id: str) -> dict | None:
    return your_db.get_namespace(ns_id)

def get_policy(ns_id: str) -> dict | None:
    return your_db.get_policy(ns_id)

# Resolve walks: DEFAULT → acme → acme/analytics → acme/analytics/prod
effective = resolve_namespace("acme/analytics/prod", get_ns, get_policy)

print(effective["capability"]["primitives"])  # {"GET", "CALL"}
print(effective["budget"]["compute_usd"])     # 0.02
print(effective["dial_ceiling"])              # 0.3333
print(effective["deny"]["rules"])             # [{resources: ["/secret/*"], ...}]
```

## Pattern Matching in Policies

Operations and resources in capability envelopes use **glob patterns**:

| Pattern | Matches |
|---------|---------|
| `*` | Everything |
| `db.*` | `db.query`, `db.scan`, `db.aggregate` |
| `/sync/database/*` | `/sync/database/users`, `/sync/database/orders` |
| `llm.generate` | Exactly `llm.generate` |

When namespaces compose, patterns use **subsumption**: a child pattern must be subsumed by (fit within) a parent pattern. A child can't grant `db.*` if the parent only allows `db.query`.

## Namespaces and Federation

Namespaces are the federation boundary:

- **L0 hashes never leave a namespace** (F8)
- **Consent edges** define which namespaces can share L1-L3 observations
- **Trust scores** are computed per principal per namespace domain
- **Budget** is allocated and tracked per namespace

When you run `spl federation grant`, you're granting one namespace permission to see another's observations at specified hash levels.
