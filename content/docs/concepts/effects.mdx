title: The Effect Algebra

Every computation in Syncropel decomposes into **effects** — atomic units with a primitive, input shape, output shape, operation, and parameters. This isn't a design choice; it's a mathematical property. Four primitives and five shapes form a closed algebra under composition.

## 4 Primitives

These are **Frozen Foundation F1** — they will never change.

| Primitive | What It Does | Example |
|-----------|-------------|---------|
| **GET** | Read or fetch data from a source | Query a database, read a file, call an API |
| **PUT** | Write or store data to a destination | Insert a row, upload a file, send a message |
| **CALL** | Invoke a computation or external service | Run an LLM, execute a function, trigger a webhook |
| **MAP** | Transform data from one form to another | Filter rows, aggregate values, parse JSON |

Any computational action — no matter how complex — decomposes into a sequence of these four. A machine learning pipeline is GET (load data) then MAP (transform) then CALL (train model) then PUT (save results). An API integration is GET then MAP then PUT.

**Why only 4?** Because this set is:
- **Closed under composition** — combining primitives produces more primitives
- **Hashable** — enables the [4-level hash hierarchy](/docs/concepts/hash-levels)
- **Verifiable** — the symbolic validator checks every effect against governance
- **Minimal** — adding a 5th primitive would break all existing hashes across every registry

## 5 Data Shapes

These are **Frozen Foundation F2** — they will never change.

| Shape | What It Means | Example |
|-------|--------------|---------|
| **VOID** | No data (unit type) | A side-effect with no return value |
| **ONE** | Exactly one value | A single row, a single response |
| **OPTIONAL** | Zero or one value | A lookup that might return nothing |
| **MANY** | Ordered collection | Query results, a list of items |
| **KEYED** | Key-value collection | A dictionary, a config map |

Every effect has an **input shape** and an **output shape**. Together they define the data flow:

```
GET  ONE→MANY       Fetch rows matching a key
MAP  MANY→ONE       Aggregate a collection to a single value
CALL ONE→ONE        Send a request, get a response
PUT  MANY→VOID      Write results (no return)
```

## Shape Compatibility

When connecting effects in a sequence, the output shape of one effect must be **compatible** with the input shape of the next. This is **Frozen Foundation F11**:

| Output Shape | Compatible Input Shapes |
|-------------|------------------------|
| VOID | VOID |
| ONE | ONE, OPTIONAL, MANY, KEYED |
| OPTIONAL | OPTIONAL, MANY, VOID |
| MANY | MANY, OPTIONAL, ONE |
| KEYED | KEYED, MANY, ONE |

The governance validator enforces this at Check 3 (shape flow). Incompatible connections are rejected before execution.

## Effect Structure

Every effect has five components:

```
Effect = Primitive × Input Shape × Output Shape × Operation × Parameters
```

| Component | Required | Description |
|-----------|----------|-------------|
| **Primitive** | Yes | One of GET, PUT, CALL, MAP |
| **Input Shape** | Yes | One of VOID, ONE, OPTIONAL, MANY, KEYED |
| **Output Shape** | Yes | One of VOID, ONE, OPTIONAL, MANY, KEYED |
| **Operation** | No | Specialization (e.g., `db.query`, `llm.generate`, `http.post`). Defaults to lowercase primitive if absent (F15). |
| **Parameters** | No | Runtime values (e.g., `{"table": "users", "limit": 100}`) |

## Operations

Operations specialize primitives without changing the algebra. You can define any operation:

```
GET with operation "db.query"     → Database read
GET with operation "http.get"     → HTTP fetch
GET with operation "file.read"    → File read
CALL with operation "llm.generate" → LLM inference
CALL with operation "webhook.fire" → Webhook trigger
```

Operations are matched via **glob patterns** in governance policies:
- `db.*` matches `db.query`, `db.scan`, `db.aggregate`
- `*` matches everything
- Policies use operation patterns to control what a session can do

**Operation Fallback (F15)**: If no operation is specified, it defaults to the lowercase primitive — `GET` becomes `"get"`, `MAP` becomes `"map"`.

## Hashing: Privacy from Structure

The 4-primitive + 5-shape algebra enables **content-addressed hashing at 4 levels of detail**:

| Level | What's Hashed | Privacy | Use |
|-------|--------------|---------|-----|
| **L0** (Exact) | Primitive + shapes + operation + parameters | Maximum | Local replay (never shared) |
| **L1** (Structural) | Primitive + shapes + operation | High | Team/org pattern matching |
| **L2** (Flow) | Primitive + shapes | Medium | Cross-org structure matching |
| **L3** (Intent) | Shapes only | Minimum | Universal intent matching |

L0 hashes **never leave your namespace** (F8). Higher levels progressively strip detail, enabling privacy-preserving knowledge sharing across organizations.

Learn more: [Hash Levels](/docs/concepts/hash-levels)

## Example: Full Effect Sequence

A data analysis workflow:

```python
effects = [
    {"primitive": "GET",  "input_shape": "ONE",  "output_shape": "MANY",
     "operation": "db.query", "parameters": {"table": "customers"}},

    {"primitive": "MAP",  "input_shape": "MANY", "output_shape": "MANY",
     "operation": "filter",  "parameters": {"where": "active = true"}},

    {"primitive": "CALL", "input_shape": "MANY", "output_shape": "ONE",
     "operation": "ml.predict", "parameters": {"model": "churn-v2"}},

    {"primitive": "PUT",  "input_shape": "ONE",  "output_shape": "VOID",
     "operation": "db.insert", "parameters": {"table": "predictions"}},
]
```

The governance validator checks every effect against the session's SCT:
- **Check 3**: Is `GET` in the capability envelope? Is `db.query` allowed by the operation globs?
- **Check 4**: Does any deny rule block `db.query` on the `customers` table?
- **Check 5**: Does the session have budget remaining?
- **Check 6**: Is the dial position within the dial ceiling?

## Using the Library

```python
from syncropel_registry_core.hashing import compute_hashes

effects = [
    {
        "primitive": "GET",
        "input_shape": "ONE",
        "output_shape": "MANY",
        "operation": "db.query",
        "parameters": {"table": "users"},
    }
]

hash_l0, hash_l1, hash_l2, hash_l3 = compute_hashes(effects)
# L0 = exact (includes parameters) — never leaves local namespace
# L1 = structural (primitive + shapes + operation)
# L2 = flow (primitive + shapes)
# L3 = intent (shapes only) — safest to federate
```
