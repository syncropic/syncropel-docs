Everything you keep in your workspace forms a **library**: a collection of things you've made that you can search and filter, not just a folder tree you navigate by remembering where you put something.

## A file is a record pointing at content

In most systems a file is bytes at a path. Syncropel separates the two:

- The **content** is identified by what it contains, so identical content is stored once and its address never changes.
- A **record** points at that content and holds its meaning: its type, its name, who made it and when.

You still see familiar names and folders, but a file's identity is its content and its record, not a path that can change.

You can keep **any content type**: a markdown document, a data record, an image, a PDF, any file. See [Files](/docs/concepts/files) for the model and [Files in Studio](/docs/guides/files-in-studio) for the day-to-day UI.

## Versioning is built in

Records never change. "Editing" a file saves a new version and the old one still exists. The **history of a thing is its thread**: the ordered trail of versions and changes. You get an audit trail and can look back without turning anything on.

## Organize by meaning, not by hierarchy

You can organize by **what things are and how they relate** (types, threads, metadata) and ask for what you want, instead of navigating to where you filed it. A folder view is available for familiarity.

**Finding things:** browse everything, filter by type and recency, or use [Find](/docs/guides/find): one query searches file names, the text *inside* your files (text, Markdown, code and CSV; PDFs and images are not searched by content), and your conversations, with snippets showing why each result matched. "Find things like this" (meaning-based search) additionally works wherever an [embedding provider](/docs/guides/search) is configured.

## "Made by you"

When you create or upload something, the library records that **you** made it. Your own files read as yours; things produced on your behalf by an assistant are attributed to that work. "Who made this" is always answerable.

## Reaching your library programmatically

Everything in the UI is available through the API and the SDKs, so an app or script can add, read, list and manage content directly:

- **TypeScript / JavaScript**: the `client.data` surface in the [SDK data plane guide](/docs/guides/sdk-data-plane).
- **Python**: the same `client.data` surface in the Python SDK.

These give you create, read, list and delete, plus safe edits that only save if the file is unchanged, so a tool never overwrites a file someone else just changed.

## In short

- Your library is **searchable**, not just a path tree.
- A file is a **record pointing at content**; any content type is welcome.
- **Versioning is built in**: records never change, and history is the thread.
- Everything is reachable through the **API and SDKs**, with safe concurrent edits.
