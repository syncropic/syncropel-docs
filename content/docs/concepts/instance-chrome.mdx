A [workspace](/docs/concepts/workspaces) describes one screen. The
**instance chrome** describes everything *around* the screens: the
navigation rail down the side, the side panels, and the footer with your
identity and status. It is the frame your workspace sits in.

Like a workspace, the chrome is a record. To change your navigation or rename your instance, you write a
`core.instance.shell.v1` record and the frame updates. No code change or redeploy is needed.

Five record kinds describe an instance: its
[identity](/docs/concepts/actors), its landing page (`core.site.v1`),
its [workspaces](/docs/concepts/workspaces) (`core.workspace.v1`), its
description (`core.instance.metadata.v1`), and its chrome
(`core.instance.shell.v1`).

## The four regions

A chrome record describes four layout regions. Each is optional. Leave
one out and a default is used.

| Region | Where it sits | Typical content |
|---|---|---|
| `rail` | The primary navigation column. | Links to your workspaces, sections, the home route. |
| `sidebar` | The context panel beside the main content. | Recent activity, the landing surfaces on your home page. |
| `drawer` | An overlay panel that slides over the content. | Status, tool palettes, secondary navigation. |
| `footer` | The strip along the bottom. | Status indicators, your identity chip, a version tag. |

These say where a piece of chrome belongs, not how it is drawn. On desktop the
`rail` runs down the left; on mobile it becomes a bottom tab bar; in a
terminal it becomes a menu. You write it once and each screen type displays it its own way.

## The shape

A chrome body is a record of kind `core.instance.shell.v1`.

```json
{
  "kind": "core.instance.shell.v1",
  "schema_version": "1.0.0",
  "lifecycle": "published",
  "owner": "did:sync:user:you",
  "extends": "default-latest",
  "meta": {
    "title": "My Instance",
    "default_route": "/home"
  },
  "regions": {
    "rail":    { "srp": "0.9", "root": { } },
    "sidebar": { "srp": "0.9", "root": { } },
    "drawer":  null,
    "footer":  { "srp": "0.9", "root": { } }
  }
}
```

| Field | What it does |
|---|---|
| `lifecycle` | `draft` (authored, only you see it), `published` (live for everyone), or `archived` (retired; the default chrome is used). |
| `owner` | Your DID. This marks the chrome as yours. |
| `extends` | Optional. Use the built-in default (`default-latest`) for any region you leave out, instead of declaring all four yourself. |
| `meta.title` | The instance name shown in the browser tab and the masthead. |
| `meta.default_route` | The path you land on after switching into this instance. |
| `regions` | The four regions. A region set to `null` renders nothing; a region left out is inherited from `extends`; a region with a document renders that document. |

Each region's value is a **projection document**, the same screen-description format a workspace's regions use. See
[Projections](/docs/guides/projections) for the document format.

## Authoring your chrome

The `spl chrome` command authors the record for you, starting from a
bundled template.

```bash
spl chrome init --template personal   # scaffold a draft from a template
spl chrome show                       # inspect the current draft
spl chrome validate my-shell.json     # check a file for errors, no workspace needed
spl chrome publish                    # promote the draft to live
spl chrome archive                    # retire it, fall back to the default
```

`init` takes one of four templates (`personal`, `graph-showcase`,
`library`, or `team`), each a different starting point. A draft is
private to you until you `publish` it. See the
[CLI reference](/docs/reference/cli#chrome) for the full command surface.

## Fetching your chrome

Studio loads your chrome with one request:

- `GET /v1/instance/bootstrap` returns your published chrome, your
  instance description, and the viewer's identity together. It is a
  **public** endpoint: an anonymous visitor gets your public chrome, and a
  signed-in viewer also sees what they are allowed to do.

To fetch only the chrome, `GET /v1/instance/shell`
returns the `core.instance.shell.v1` record on its own. Both
are covered in the [API reference](/docs/reference/api#instance).

If no chrome has been published, a default is used, so a workspace always has a frame.

## What chrome is not

- **It is not a workspace.** A workspace is one interactive screen;
  chrome is the frame that holds every screen.
- **It does not grant power.** Chrome decides what is *shown*, not what
  is *allowed*. A rail link to a screen a viewer cannot use simply will
  not work. Permissions are still enforced by your workspace.
- **It carries no data.** Like a workspace, a chrome record holds
  queries, not fixed content. The same chrome shows each
  viewer their own records.
