## How Governance Works

When you start a session with Syncropel, the system computes your permissions based on:

1. **Your namespace** — which project/organization you're working in
2. **Your trust score** — computed from your track record
3. **Your policies** — capability grants, deny rules, and budgets set by your organization

These permissions are encoded in a session token and enforced on every action. If an action violates the rules, it's blocked.

## What Gets Checked

Every action is validated against 10 governance checks:

1. **Revocation** — Is your session still valid?
2. **Policy freshness** — Are the policies up to date?
3. **Capability** — Do you have permission for this action type?
4. **Deny rules** — Is this action explicitly forbidden?
5. **Budget** — Is there budget remaining?
6. **Trust level** — Does your trust score allow this autonomy level?
7. **Hash access** — Can you access this level of detail?
8. **Per-action budget** — Does this specific action fit within limits?
9. **Structural integrity** — Is the action well-formed?
10. **Human approval** — Does this action require human sign-off?

If any check fails, the action is denied with a clear reason.
