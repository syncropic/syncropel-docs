## What is Syncropel?

Syncropel sits between your code and your LLM. Change one line — your `base_url` — and get full observability on every API call: model, tokens, cost, and latency, all recorded automatically.

```bash
curl -sSf https://get.syncropic.com/spl | sh
spl init
spl serve
```

Then point your SDK to `http://localhost:9100`. Every call is now recorded.

## The Protocol

Syncropel is **verification infrastructure for AI computation** — a formal algebra and governance protocol that any AI system can embed to become trustworthy. Like TLS for the web, Syncropel is invisible infrastructure: your agents run, Syncropel verifies.

The protocol is built on immutable foundations: **effect primitives** (GET, PUT, CALL, MAP), **data shapes** (VOID, ONE, OPTIONAL, MANY, KEYED), **hash levels** (Exact, Structural, Flow, Intent), and a **deterministic governance pipeline** — all enforced by mathematics, not promises.

## The Protocol at a Glance

| Foundation | What | Frozen? |
|-----------|------|---------|
| **Primitives** | GET, PUT, CALL, MAP | Yes (F1) |
| **Shapes** | VOID, ONE, OPTIONAL, MANY, KEYED | Yes (F2) |
| **Hash Levels** | Exact, Structural, Flow, Intent | Yes (F6) |
| **Dial Zones** | REPLAY \[0,1/3), ADAPT \[1/3,1/2), EXPLORE \[1/2,2/3), CREATE \[2/3,1\] | Yes (F5) |
| **Namespace Levels** | DEFAULT, ORG, PROJECT, ENV, JOB | Yes |
| **Governance Checks** | CRL, Policy freshness, Capability, Deny, Budget, Dial, Hash level, Budget guard, Structural, HITL | Yes |

These are **Frozen Foundations** — they will never change. Any computation decomposes into these primitives. Any governance decision reduces to these checks.

## How It Works

```
Session Creation (Registry)          Effect Execution (Validator)
═══════════════════════════          ═══════════════════════════
1. Authenticate principal            1. Check SCT signature
2. Resolve namespace hierarchy       2. Check CRL (not revoked)
3. Compute capability envelope       3. Check capability envelope
4. Apply deny constraints            4. Check deny constraints
5. Compute trust score               5. Check session budget
6. Derive dial ceiling               6. Check dial ceiling
7. Build budget envelope             7. Check hash level access
8. Determine hash access             8. Check per-effect budget
9. Issue SCT (signed token)          9. Check structural limits
10. Record audit event               10. Check HITL approval
```

Governance is computed **once** at session creation, encoded in a Session Capability Token (SCT), then enforced at every effect execution through pure arithmetic and set membership — no database lookups, no rule evaluation.
