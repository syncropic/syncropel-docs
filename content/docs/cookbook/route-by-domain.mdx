---
title: Route by domain
description: Send code work to one agent and operations work to another, with one rule per domain.
---

## Problem

Your team has two AI agents: one for code (`did:sync:agent:dev`) and one for operations (`did:sync:agent:ops-bot`). When you open a task with `domain: code`, you want the code agent to get it. When you open one with `domain: ops`, you want the ops agent. You don't want to name the agent every time, or write one rule per person.

## Recipe

Two routing rules, one per domain. Each is written as a short condition (a CEL expression).

```bash
# Send every task with domain=code to the dev agent.
spl config add-rule \
  --name "route-code-to-dev" \
  --expression "record.act == 'INTEND' && record.body.domain == 'code'" \
  --target "did:sync:agent:dev"

# Send every task with domain=ops to the ops bot.
spl config add-rule \
  --name "route-ops-to-bot" \
  --expression "record.act == 'INTEND' && record.body.domain == 'ops'" \
  --target "did:sync:agent:ops-bot"

# Check the rules are in place.
spl config list-rules
```

That's it. From now on, any task opened with the right `body.domain` is routed automatically.

Try it:

```bash
# This goes to did:sync:agent:dev.
spl task add "Refactor the auth middleware" \
  --alias REFACTOR-001 \
  --assign did:sync:agent:dev \
  --domain code

# This goes to did:sync:agent:ops-bot.
spl task add "Rotate the TLS cert on api.example.com" \
  --alias CERT-ROTATE-001 \
  --assign did:sync:agent:ops-bot \
  --domain ops
```

Or leave out `--assign` and let the rule choose the agent (see [The Engine: routing](/docs/concepts/engine)).

## The trade-off

**These rules match every `INTEND` record, not just new tasks.** If you add an `INTEND` for some other reason (a test ping, say) with `body.domain: code`, it also goes to the dev agent. To avoid that, narrow the condition:

```bash
--expression "record.act == 'INTEND' && record.body.domain == 'code' && record.body.task == true"
```

The `record.body.task == true` part limits the rule to new tasks. If other rules also match tasks, set a priority (a higher number is checked first).
