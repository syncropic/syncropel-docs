---
title: Escalate to a human on low confidence
description: An AI model handles the normal case, and a person gets the question when the model is not confident. One setup, no routing rules.
---

## Problem

Your support triage system classifies incoming tickets. An AI model handles the common cases (shipping question, refund request, account lock). Sometimes it isn't sure, and you'd rather hand those cases to a person than act on a shaky guess.

You want: ask the AI model first; if its confidence is below 0.7, pass the ticket to a named support lead. All in one query.

## Recipe

The `escalate` pattern with two tiers. Tier 1 is Claude Sonnet. Tier 2 is Priya (the support lead). It moves to tier 2 when confidence is below the threshold.

```json
{
  "kind": "infer.query.v1",
  "input": {
    "inline": {
      "ticket_id": "SUP-4821",
      "subject": "Package arrived open",
      "body": "Hi, my box arrived with the tape cut and one item missing. Help?"
    }
  },
  "responders": [
    { "kind": "llm", "model": "~sonnet" },
    { "kind": "actor", "did": "did:example:priya", "capability": "support:triage" }
  ],
  "fold": { "function": "best_of" },
  "orchestration": {
    "pattern": "escalate",
    "tiers": [
      { "responders": [{ "kind": "llm", "model": "~sonnet" }] },
      { "responders": [{ "kind": "actor", "did": "did:example:priya" }] }
    ],
    "escalation_expression": "fold.answer.confidence < 0.7"
  },
  "answer_shape": {
    "kind": "core.triage_decision.v1",
    "required_fields": ["body.category", "body.priority", "body.confidence"]
  },
  "side_effects": {
    "reversible": true,
    "max_cost_usd": 0.50,
    "max_latency_secs": 14400
  }
}
```

Run it:

```bash
spl infer --query-file triage-query.json --wait --poll-timeout-secs 14400
```

## The high-confidence path

The AI model returns:

```json
{
  "category": "damage_claim",
  "priority": "p2",
  "confidence": 0.91,
  "rationale": "Explicit mention of damage + missing item."
}
```

`fold.answer.confidence` is 0.91, which is not below 0.7, so nothing is escalated and the answer is saved as the result (a `KNOW`). It takes about 5 seconds and costs about $0.003.

The records on the query's thread (see them with `spl thread records <id>`):

```text
clock  actor                    act     body.kind
  1    did:example:support-sys  INTEND  infer.query.v1
  2    did:sync:system:engine   CALL    infer.call.v1      (→ sonnet)
  3    did:sync:llm:sonnet      DO      core.triage_decision.v1
  4    did:sync:system:engine   KNOW    core.triage_decision.v1   ← final
```

## The escalation path

The AI model returns:

```json
{
  "category": "account_issue",
  "priority": "p3",
  "confidence": 0.58,
  "rationale": "Unclear whether to route to damage-claims or fraud team."
}
```

`fold.answer.confidence < 0.7` is true, so the ticket goes to Priya.

The records:

```text
clock  actor                    act     body.kind                              notes
  1    did:example:support-sys  INTEND  infer.query.v1
  2    did:sync:system:engine   CALL    infer.call.v1                          → sonnet (tier 1)
  3    did:sync:llm:sonnet      DO      core.triage_decision.v1                confidence=0.58
  4    did:sync:system:engine   LEARN   infer.orchestration.escalate.state.v1  tier=0 failed
  5    did:sync:system:engine   CALL    infer.call.v1                          → priya (tier 2)
  6    did:example:priya        DO      infer.accept.v1                        eta_seconds=7200
  7    did:example:priya        DO      core.triage_decision.v1                confidence=0.95
  8    did:sync:system:engine   KNOW    core.triage_decision.v1                ← final, priya's answer
```

Priya is notified (live in her browser if it's open, otherwise by webhook, Slack or SMS). She first sends `infer.accept.v1` with `eta_seconds: 7200`, which tells the query to wait 2 more hours without counting as her answer. She then submits her verdict, which does count. With two answers, `best_of` picks the one from the more trusted contributor (Priya at trust 0.95 vs Sonnet at 0.62), so Priya's answer is saved in full.

## Why escalate instead of verify?

`verify` runs **both** the main model and the checker every time. `escalate` only goes to tier 2 when tier 1 isn't confident enough. If 90% of your tickets are handled confidently at tier 1, `escalate` costs about one AI call most of the time and only reaches Priya for the hard 10%. `verify` would always use both.

## The trade-off

`escalate` runs tiers one after another. Tier 2 doesn't start until tier 1 answers. That is its benefit, but the worst case takes as long as all tiers together: if Priya takes 2 hours, the query takes about 2 hours and 5 seconds.

A person's reply time can go past your `max_latency_secs`. Allow plenty: 14400 seconds (4 hours) or 86400 (24 hours) are reasonable when it isn't urgent. If the query times out before Priya replies, it ends with `latency_timeout` and the AI model's low-confidence answer is never saved (you get an error record instead).

If you want the AI model's best answer kept even when the person times out, use `retry_on_low_confidence` with `max_attempts: 2` and retry with stronger models instead. That keeps everything automatic.

## Try it on a test workspace

Register Priya:

```bash
spl actor register did:example:priya --category agent --display-name "Priya (support triage)"
```

Trust is earned from verdicts, not set at registration: Priya builds trust in the `support` domain as her judgments are approved, and `best_of` uses that trust. Run the query as above and watch the thread. To simulate Priya's reply, add her `DO` yourself with `spl do`:

```bash
spl do "triage response" \
  --thread <query-thread-id> \
  --actor did:example:priya \
  --body '{"kind":"core.triage_decision.v1","category":"damage_claim","priority":"p1","confidence":0.95}'
```

The result is saved once her `DO` is added.
