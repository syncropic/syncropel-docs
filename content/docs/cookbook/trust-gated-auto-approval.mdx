---
title: Trust-gated auto-approval
description: Let highly trusted actors go ahead without waiting for human review, and require review for the rest. One policy, one threshold, no per-task setup.
---

## Problem

You use Syncropel for real work. Agents you trust (those with dozens of approved completions in a domain) shouldn't wait for you to approve every small change. It wastes your attention and their time. But you still want a review step when trust is low, and you don't want to keep a list of approved actors by hand.

## Recipe

One policy that applies proposals automatically from actors above a trust level, and shows everything else to you to decide.

```bash
# Apply automatically when the actor's trust is at least 0.80 in the
# task's domain AND it rests on at least 10 outcomes (so the score
# isn't just a few lucky results).
spl config add-decision-policy \
  --name "auto-apply-high-trust" \
  --action auto_apply \
  --priority 200 \
  --expression '
    trust(record.actor, record.body.domain) >= 0.80 &&
    trust_count(record.actor, record.body.domain) >= 10
  '

# Everything else goes to a person to decide.
spl config add-decision-policy \
  --name "present-for-review" \
  --action present \
  --priority 10 \
  --expression "true"

# Verify.
spl config list-decision-policies
```

The priority 200 policy is checked first. If its condition holds, the proposal is applied straight away: the routing rule it suggests is saved as a `LEARN` on `th_engine_config`, and matching records are routed by it from then on. The priority 10 policy is checked last and catches everything else, listing it in `spl decisions list` for you to decide.

Try it:

```bash
# Start some work. If the system proposes a routing rule and the
# proposing actor is above the threshold, it is applied automatically.
# Otherwise it appears here:
spl decisions list

# Decide yourself:
spl decisions approve <id>
spl decisions reject <id>
```

## The trade-off

**Automatic approval is real automation.** A flawed proposal from a trusted actor can create a bad routing rule that sends records to the wrong place. Two ways to limit that:

1. **Watch for drift alerts in the actor's domain.** If trust starts falling because automatically applied rules are giving bad results, you are alerted, but only after some damage.
2. **Add a higher-priority policy for important namespaces.** In `acme-corp/payments/prod` you may not want any automatic approval, however high the trust:

   ```bash
   spl config add-decision-policy \
     --name "never-auto-apply-in-prod-payments" \
     --action present \
     --priority 1000 \
     --expression "record.body.namespace.startsWith('acme-corp/payments/prod')"
   ```

   Priority 1000 is checked before priority 200, so production namespaces are always shown to you for review.

The threshold of 0.80 is a starting point. Adjust it to your risk tolerance: 0.90 is more cautious, 0.70 is more relaxed, and `trust_count >= 50` (instead of 10) raises the bar further.
