---
title: Scheduled daily digest
description: Run a scheduled job every morning at 09:00 that asks an agent to summarise what closed in the last 24 hours.
---

## Problem

You want a daily summary of which tasks closed, what the agent runs cost, and any alerts from the last 24 hours. It should appear on a shared thread at 09:00 every day without anyone starting it. An agent you already have can write it.

## Recipe

One scheduled trigger. It asks your review agent at 09:00 to produce the daily digest.

```bash
# Create the scheduled trigger.
spl config add-trigger \
  --name "daily-digest-0900" \
  --schedule "0 9 * * *" \
  --target "did:sync:agent:reviewer" \
  --goal "Summarise yesterday's closed tasks, dispatch costs, and alerts. Emit a KNOW on th_daily_digest with body.topic=daily_digest." \
  --budget 0.50 \
  --timeout 600 \
  --max-concurrent 1

# Verify.
spl config list-triggers

# See when it last ran and what it produced.
spl config trigger-history --limit 10
```

The schedule `0 9 * * *` runs at 09:00 every day (minute 0, hour 9, any day, any month, any weekday). It is the usual five-field cron form. Each time it runs, the trigger asks the target agent to do the goal and saves a `KNOW` record on `th_engine_config` noting that it ran. The agent's own work (collecting the data and writing the digest) happens on a separate thread.

The agent should write the digest to the same thread every day. Here that is `th_daily_digest`. Create it once if it doesn't exist:

```bash
# Open the digest thread so it has a name.
spl intend "Daily digests" --thread th_daily_digest
```

Each later `KNOW` from the agent lands on that thread, building a dated log of daily summaries. `spl thread records th_daily_digest` reads it.

## The trade-off

**Scheduled triggers run on one workspace.** If you run several workspaces together, the trigger runs on the one that holds the `th_engine_config` thread (usually the coordinating one). If that workspace is offline at 09:00, the digest is skipped and not made up later.

**The goal text is all the agent sees.** A detailed goal produces a better digest. The goal above asks for a specific thread (`th_daily_digest`) and a specific body topic (`daily_digest`), which means you can find the digest records later with a rule (for example to send them to a notification webhook, or to alert when one is missing). A vague goal ("summarise yesterday") works but gives less consistent output.

**The budget limits each run.** 0.50 USD is enough for a focused digest of about 50 closed tasks. Raise it for a bigger team; lower it to keep digests short. If a run goes over 600 seconds or over budget, it is stopped with `TIMEOUT`; the next day's run is unaffected.
