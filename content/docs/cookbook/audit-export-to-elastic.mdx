---
title: Audit export to Elastic
description: Send Syncropel's security-related records to Elasticsearch or another security monitoring (SIEM) tool, where you can search them.
---

## Problem

Security events (failed sign-ins, decision outcomes, agent run outcomes, governance denials, refused permissions) need to reach your SIEM so you can search them next to your other logs, such as firewall and sign-in logs. You don't want to build a custom integration. You want to take what Syncropel already exports and send it on.

## Recipe

`spl audit export` prints one JSON object per line (JSONL). Send that to your SIEM's intake address.

```bash
# Hourly export. Run this every hour from cron; it covers the last 65 minutes,
# which leaves a 5-minute overlap so nothing is missed.
spl audit export --since 65m | \
  curl -s -X POST "https://elastic.example.com:9200/syncropel-audit/_bulk" \
    -H "Content-Type: application/x-ndjson" \
    -H "Authorization: ApiKey $ELASTIC_API_KEY" \
    --data-binary @-
```

Elasticsearch's bulk API accepts JSONL, so each line becomes one searchable document. The `_bulk` endpoint expects an action line before each document, and `spl audit export` prints only documents, so add the action lines with `jq`:

```bash
spl audit export --since 65m | jq -c '{"index":{}}, .' | \
  curl -s -X POST "https://elastic.example.com:9200/syncropel-audit/_bulk" \
    -H "Content-Type: application/x-ndjson" \
    -H "Authorization: ApiKey $ELASTIC_API_KEY" \
    --data-binary @-
```

For Splunk HEC, Datadog, or a generic webhook, change the curl target. The output is the same.

Drop it in cron:

```bash
# /etc/cron.d/syncropel-audit-export
0 * * * * syncropeluser /usr/local/bin/export-audit.sh
```

Here `export-audit.sh` is a script that runs the command above and handles errors and logging.

## What's in the stream

The export includes only security-related records. By default it includes:

- **`system`**: records from `did:sync:system:engine` and other system actors (settings reloads, notifications, governance events).
- **`decision`**: decisions waiting and decisions made.
- **`dispatch`**: agent run outcomes, budget used up, timeouts.
- **`governance`**: refused namespace changes, permission denials, emergency-stop records.

Export less if your SIEM charges by volume:

```bash
# Only decisions and governance.
spl audit export --since 65m --categories decision,governance
```

## The trade-off

**The export runs when you run it; it does not stream.** You run `spl audit export` on your own schedule, and it prints everything that matches since the time you give. If your SIEM needs *real-time* alerts (within a minute), hourly is too slow. For that, follow the workspace log or subscribe to live events (SSE), but then you lose the audit categories and must filter in your own pipeline.

**`--since` uses the clock, not the records.** A burst of records at the edge of a window can be split across two exports. The 5-minute overlap (`--since 65m` on an hourly cron) means some records appear twice, so let your SIEM drop duplicates by record ID. Every record has a fixed ID in the export, so this is safe.

**Permission denials go to the workspace log, not to your records.** `spl audit export` does not include them. To capture them, also collect the workspace log in your SIEM.
