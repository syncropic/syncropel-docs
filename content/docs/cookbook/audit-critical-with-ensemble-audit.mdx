---
title: Audit-critical decisions with several AI models and a check
description: Ask three AI models a compliance question, combine their answers, then require a trusted compliance officer to check the result before it is saved.
---

## Problem

You run a regulated service. Some decisions (granting a customer a waiver, approving a refund above a limit, signing off a disclosure) need a compliance sign-off even though an AI model can do the reasoning. You want several AI models to reason about the decision and a named compliance officer to approve the combined result before anything is saved.

## Recipe

The `ensemble_with_audit` pattern. Three AI models answer at the same time, `consensus` combines their answers, then the compliance officer checks the result. Conflicts are handled with `validation_error`: any inconsistency stops the query, instead of the last answer silently winning.

```json
{
  "kind": "infer.query.v1",
  "input": {
    "inline": {
      "decision": "waiver",
      "customer_id": "cust_4821",
      "amount_usd": 1200,
      "context": "Customer reports storm damage; policy allows waivers up to $1500 with compliance sign-off."
    }
  },
  "responders": [
    { "kind": "llm", "model": "~sonnet" },
    { "kind": "llm", "model": "~gpt-4" },
    { "kind": "llm", "model": "~gemini-1.5" },
    { "kind": "actor", "did": "did:example:compliance-officer", "trust_gte": 0.95 }
  ],
  "fold": { "function": "consensus", "min_quorum": 2 },
  "orchestration": {
    "pattern": "ensemble_with_audit",
    "primary_responders": [
      { "kind": "llm", "model": "~sonnet" },
      { "kind": "llm", "model": "~gpt-4" },
      { "kind": "llm", "model": "~gemini-1.5" }
    ],
    "auditor": {
      "kind": "actor",
      "did": "did:example:compliance-officer",
      "trust_gte": 0.95
    },
    "audit_expression": "audit.approved == true"
  },
  "answer_shape": {
    "kind": "core.compliance_decision.v1",
    "required_fields": ["body.decision", "body.rationale", "body.approved"]
  },
  "side_effects": {
    "reversible": false,
    "max_cost_usd": 2.00,
    "max_latency_secs": 86400,
    "obligation_resolution": "validation_error"
  }
}
```

Run it:

```bash
spl infer --query-file compliance-query.json --wait --poll-timeout-secs 86400
```

## What happens

1. The query is checked.
2. The three AI models and the compliance officer are chosen.
3. The three AI models are asked at the same time. The officer is not asked yet.
4. It waits for their answers. `min_quorum: 2` means at least 2 must reply.
5. `consensus` combines their answers.
6. The combined answer is sent to the compliance officer.
7. It waits for the officer's reply (a `DO` record).
8. It checks `audit.approved == true` in that reply.
9. If approved: the combined answer is saved as the result (a `KNOW`), with an `audit` field attached.
10. If rejected: a `KNOW` is saved with `body.audit.rejected: true` and the officer's `body.rationale`. The decision is NOT carried out.

## Result when rejected

```json
{
  "act": "KNOW",
  "body": {
    "kind": "core.compliance_decision.v1",
    "approved": false,
    "audit": {
      "auditor": "did:example:compliance-officer",
      "approved": false,
      "rationale": "Customer's prior claim in 2025 suggests pattern; waiver not consistent with policy discretion.",
      "timestamp": "2026-04-24T14:22:11Z"
    }
  }
}
```

Systems that act on `body.approved` will skip the waiver. The record is kept, so nothing is lost.

## Why `validation_error`?

`obligation_resolution: "validation_error"` means: if answers conflict (one has `body.fulfills: "..."` and another `body.cancels: "..."`), the query stops with `obligation_conflict` instead of quietly picking one. For compliance work you want it to stop.

Use `last_writer_wins` (the default) when conflicts are rare and you are happy for Syncropel to pick the latest. Use `fulfills_wins` when a fulfilment should always win over a cancellation.

## The trade-off

`ensemble_with_audit` is the most expensive pattern. You pay for all the AI models and for the auditor's step. If the auditor is a person, you also wait: an overnight window is normal.

Use it when a wrong decision would cost more than the audit. Skip it when the decision can be undone, matters little, or is already covered by another approval.

Also, `consensus` only works if the models give answers in the same shape. Ask them all for the same JSON (decision, rationale and an approved true/false), or every answer counts as different and `consensus` falls back to `best_of`.

## Try it on a test workspace

Register the compliance officer actor:

```bash
spl actor register did:example:compliance-officer --category user --display-name "Compliance officer"
```

Then set up a webhook for them, or have them open a live-updates (SSE) connection to `GET /v1/responders/did:example:compliance-officer/inbound`. For a test, the easiest way is a webhook to `webhook.site` that you reply to by hand.
