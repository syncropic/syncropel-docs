---
title: Translate with human verification
description: One AI model translates, a second checks it, and a person steps in only when the two disagree.
---

## Problem

You need reliable English to Spanish translations for text your users see. One AI model usually gets it right but sometimes mishandles idioms, tone or formality. You have a trusted reviewer (Alice, a native Spanish speaker), but she can't review every translation. You want her only when the AI models disagree.

## Recipe

One `spl infer` call using the `verify` pattern. Claude Sonnet translates, GPT-4 checks, and Alice settles any disagreement.

```bash
spl infer "Translate to Spanish: 'The early bird catches the worm.'" \
  --kind core.translation.v1 \
  --responder llm:sonnet \
  --responder llm:gpt-4 \
  --responder actor:did:example:alice \
  --orchestration verify \
  --fold best_of \
  --budget 0.40 \
  --timeout 1800 \
  --wait
```

When they agree, the answer (a `KNOW` record) arrives in about 5 to 15 seconds and Alice never hears about it. When they disagree, the question goes to Alice. She is notified through the channel she has set up (live updates, a webhook, Slack, or a digest email, depending on her availability). She submits a `core.translation.v1` `DO` record with the correct answer, and that becomes the final `KNOW`.

Output when the two agree:

```text
answer:
  {
    "text": "A quien madruga, Dios le ayuda.",
    "target_language": "es",
    "confidence": 0.92
  }
provenance (2 contributors)
trust_summary: mean 0.81 min 0.78 max 0.84 n=2
cost: $0.0062
fold: best_of
thread: th_4a7b3c...
know_record: 8e2f19a4...
```

When they disagree and Alice steps in, `trust_summary` counts three contributors and the chosen answer is Alice's.

## The trade-off

`verify` costs about twice as much as asking one AI model (the translator plus the checker). That is the point: you pay for independent confirmation. If your translations are low-stakes (internal logs, developer-facing text), use `single_shot` with one model instead.

By default the two answers must be 85% similar in structure (`agreement_threshold` 0.85). For translation, where the wording differs but the meaning is the same, you may want to lower it:

```json
{
  "orchestration": {
    "pattern": "verify",
    "primary": [{ "kind": "llm", "model": "~sonnet" }],
    "verifier": { "kind": "llm", "model": "~gpt-4" },
    "tiebreaker": { "kind": "actor", "did": "did:example:alice" },
    "agreement_threshold": 0.75
  }
}
```

Send it with `spl infer --query-file`:

```bash
spl infer --query-file query.json --wait
```

A lower threshold means fewer questions for Alice but more cases where the two models "agree" even though the translation is wrong.

## Try it on a test workspace

With a local workspace and the Sonnet and GPT-4 providers set up, register Alice as an actor:

```bash
spl actor register did:example:alice --category agent --display-name "Alice (en-es translator)"
```

Then run the infer command above. If Alice doesn't respond, the query ends with `latency_timeout` after 1800 seconds. To simulate her reply in a test, add her `DO` yourself with `spl do` (a `core.translation.v1` `DO` on the same thread).
