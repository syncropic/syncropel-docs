This tutorial gets you from zero to a running local registry with governance in 5 minutes.

## Prerequisites

- Python 3.12 or later

## Step 1: Install the CLI

```bash
curl -fsSL https://get.syncropic.com/spl | sh
```

The installer detects your package manager (pipx, uv, or pip) and installs `spl` with local registry support. You can also install manually:

```bash
# With pipx (recommended — isolated install)
pipx install "syncropel-cli[serve] @ git+https://github.com/syncropic/syncropel-cli.git@v0.3.0"

# Or with uv
uv tool install "syncropel-cli[serve] @ git+https://github.com/syncropic/syncropel-cli.git@v0.3.0"

# Or with pip
pip install "syncropel-cli[serve] @ git+https://github.com/syncropic/syncropel-cli.git@v0.3.0"
```

Verify the installation:

```bash
spl version
# syncropel-cli 0.3.0
```

## Step 2: Start Your Local Registry

```bash
spl serve
```

This starts a full governance-aware registry on your machine:

```
Registry started at http://localhost:9100
Database: ~/.syncropel/registry.duckdb (persistent)
```

The local registry is DuckDB-backed and persistent — your data survives restarts. It exposes the same API as the production registry, so SDKs connect identically.

**Leave this running** and open a new terminal for the remaining steps.

## Step 3: Create a Namespace

Namespaces are the unit of governance. Every policy, budget, and trust score lives within a namespace.

```bash
spl namespace create myproject -j
```

```json
{
  "id": "myproject",
  "parent": "default",
  "created_at": "2026-02-24T10:00:00Z"
}
```

This creates `myproject` as a child of `default`. Governance monotonically narrows: `myproject` can never have more permissions than `default`.

## Step 4: Set a Policy

Restrict what effects are allowed in your namespace:

```bash
spl policy set myproject --primitives GET,CALL -j
```

Now `myproject` only allows GET and CALL effects — no PUT or MAP. Any attempt to write data or transform it will be denied by the governance validator.

## Step 5: Check Trust

```bash
spl trust show -j
```

New principals start with a **cold-start prior** — a Wilson score based on Beta(7, 10), giving an effective score around 0.47. This places you in the ADAPT dial zone: you can replay and adapt known patterns, but you need to earn trust before creating novel ones.

Trust grows through successful observations and decays with a 30-day half-life.

## Step 6: View the Audit Trail

Every governance action is recorded:

```bash
spl audit query -j
```

You'll see audit records for the namespace creation and policy changes. Nothing happens in Syncropel without a trail.

## What Just Happened

In 5 minutes, you set up:

1. **A local registry** — persistent DuckDB store at `~/.syncropel/registry.duckdb`
2. **A governed namespace** — `myproject` inheriting from `default`, with a restrictive policy
3. **A trust baseline** — cold-start prior that unlocks more autonomy as you prove reliability
4. **An audit trail** — immutable record of every governance decision

The governance stack running locally is identical to what runs in production. Every check, every threshold, every enforcement — the same.

## All Commands

Every `spl` command supports `-j` / `--json` for structured output. Run `spl --help` for the full list, or use progressive discovery:

```bash
spl help-agent -j              # Overview (~200 tokens)
spl help-agent namespace -j    # Namespace commands (~400 tokens)
spl help-agent --conventions -j # Governance model (~500 tokens)
```
