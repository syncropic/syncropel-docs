## What you'll learn

Tasks in Syncropel are more than work items: they carry success criteria. When a task is completed and reviewed, the outcome feeds into trust scores.

## Create a task

```bash
spl task add "Add input validation to the signup form" \
  --priority high \
  --label code
```

The output shows a thread ID and an alias (like `TASK-0001`) that you can use as a shorthand.

A task can be created with its relations already set. They are saved as real links, not as text:

```bash
spl task add "Validate the phone field too" --alias TASK-0002 \
  --parent TASK-0001 \
  --depends-on TASK-0001
```

`--parent` names the task this one is a child of, `--fixes` names a defect thread this one fixes, and `--depends-on` blocks this task until the named ones are approved. Each accepts an alias, a thread id or a record id, and each is saved as a link on the new task's first record (also listed under `body.relations`), so the relation shows up in the thread graph. Every reference is checked before anything is saved. If an alias does not exist or you cannot read a thread, the whole command fails with exit code 2 and nothing is saved.

## View your tasks

```bash
spl task list
```

```
ID           STATUS   PRI    GOAL                                    ASSIGN
TASK-0001     inbox    high   Add input validation to the signup...   —
```

The task starts in `inbox` status: it exists, but nobody has started on it.

## Start working

```bash
spl task start TASK-0001
```

Status changes to `active`. This records that work has begun.

## Complete the task

When the work is done, mark it complete with a summary:

```bash
spl task done TASK-0001 --summary "Added email format and password length validation" --domain code
```

Status changes to `review`: the task is marked complete but nobody else has checked it yet.

## Review and approve

An independent reviewer confirms the work meets the criteria:

```bash
spl task approve TASK-0001 --domain code --notes "Validation logic verified, tests pass"
```

Status changes to `approved`. This creates a trust observation: evidence that the work was completed successfully in the `code` domain.

If the work shipped in a release, name the release and the verdict is linked to that release's record:

```bash
spl task approve TASK-0001 --domain code --grade 0.9 --in-release v1.2.0
```

`--in-release` also works on `spl task done`. A version with no release record is refused with exit code 2 and nothing is written. `--grade` (0 to 1) adds a quality judgment to the verdict. A plain approval without a grade adds very little to trust.

## See trust grow

```bash
spl trust
```

```
ACTOR                   DOMAIN    SUCCESS   TOTAL   TRUST
did:sync:user:you       code            1       1   0.246
```

Each approved task adds evidence. Over time, trust scores reflect a real track record, not opinions or permissions.
