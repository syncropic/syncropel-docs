## What you'll learn

A thread is a sequence of related records that make up one piece of work. Every task and conversation is a thread. In this tutorial you'll create a thread, add records to it and close it.

## Create a thread

Every INTEND opens a new thread:

```bash
spl intend "Migrate the user database to the new schema"
```

The output includes a thread ID:

```
✓ Record created on thread th_7f3a...
```

Pass this ID to add later records to the same thread.

## Add records to the thread

Record what happens as you work:

```bash
spl do "Backed up existing database" --thread th_7f3a...
spl do "Applied migration script" --thread th_7f3a...
spl know "All tables migrated, zero data loss" --thread th_7f3a...
```

Each record adds to the story of the thread: what was intended, what was done and what was observed.

## View the thread

```bash
spl thread records th_7f3a...
```

This shows every record on the thread in chronological order, with the actor, act type, and body of each record.

## List all threads

```bash
spl thread list
```

This shows all active threads with their latest activity, participant count and record count.

## Close a thread

A thread closes when a KNOW fulfills its opening INTEND. Pass `--fulfills` on the closing KNOW. With no value, it
fulfills the thread's opening INTEND.

```bash
spl know "Migration complete, all services verified" --thread th_7f3a... --fulfills
```

To fulfill a specific record rather than the thread's opening intent, name it:
`--fulfills <record-id>`. Either way the KNOW carries `body.fulfills`, and that link is what marks the thread as done. The whole chain of records, from
the intent through the work to the closing observation, is kept as a history that never changes.

## Capture insights

After completing work, record what you learned:

```bash
spl learn "Schema migrations should run in maintenance windows to avoid connection timeouts"
```

LEARN records capture insights for future work. They are kept in your memory and inform later decisions.
