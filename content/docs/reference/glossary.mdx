## A

### Actor
An identity in the system. Your app is an actor. An AI agent is an actor. Every record is attributed to an actor.

### API Proxy
The transparent proxy at localhost:9100 that forwards LLM calls to Anthropic or OpenAI while recording metadata (model, tokens, cost, latency).

## B

### Budget Envelope
A 4-dimensional constraint on session cost: compute (USD), latency (ms), quality floor \[0,1\], and risk ceiling \[0,1\]. Zero means unlimited. Budget is tracked with Decimal precision. Part of the SCT.

## C

### Console
The web dashboard at localhost:9100/console showing real-time record streams and aggregate statistics.

### Cost Estimation
Approximate USD cost computed from token counts and per-model pricing. Shown in the console and health endpoint.

### Capability Envelope
The set of effects a session is allowed to execute: primitives, shapes, operations (glob patterns), resources (glob patterns), max effects, and max depth. Resolved through namespace hierarchy via set intersection.

### Default Starting Trust
The trust baseline for new principals, giving a score of approximately 0.47. Places new entities in the ADAPT dial zone, where they can replay and adapt patterns but must earn trust before exploring or creating.

### Consent Edge
A directed permission from one namespace to another, allowing the target to see the source's observations at specified hash levels (L1-L3 only, never L0). The unit of federation.

### Content Hash
SHA-256 of the canonical JSON representation of an object. Used for identity, integrity verification, and deduplication. Always 64 lowercase hex characters.

### CRL (Certificate Revocation List)
A list of revoked principal DIDs and SCT hashes. Check 1 in the governance pipeline. When a service account is deactivated, its DID is added to the CRL.

## D

### Deny Rule
An explicit prohibition matching effects by resource patterns and/or primitives. Deny rules follow **forbid-wins** semantics: any deny at any namespace level blocks the effect. No capability grant can override a deny.

### DID (Decentralized Identifier)
A portable identity string for principals. Format: `did:sync:user:<id>`, `did:sync:sa:<id>`, `did:sync:runner:<id>`.

### Dial
A single continuous parameter on \[0, 1\] that controls the balance between deterministic replay and creative generation. Divided into 4 zones at exact fractional thresholds. See The Dial.

### Dial Ceiling
The maximum dial position a session can use. Derived as `min(identity_max, namespace_ceiling, trust_to_dial, budget_to_dial)`. Encoded in the SCT.

## E

### Effect
The atomic unit of computation. An effect combines a primitive (GET, PUT, CALL, MAP), input shape, output shape, operation, and parameters. See The Effect Algebra.

### Elevated Tier
The governance tier for sessions with dial &ge; 2/3 (CREATE zone). Adds [HITL](#hitl) approval requirements for PUT and CALL effects on top of standard governance checks.

## F

### Federation
Consent-gated sharing of observations across namespace boundaries. Registries exchange `(hash, observation_count, cost)` tuples at L1-L3 levels. Observations use automatic conflict-free merging — merging always produces the same result regardless of order.

### Forbid-Wins
The deny composition rule: if any deny rule at any level in the namespace chain matches an effect, the effect is blocked. No amount of ALLOW at a child level can override a DENY from a parent.

### Freshness Factor
Temporal decay applied to trust scores — recent activity matters more than old activity.

### Frozen Foundations
15 immutable protocol constants (F1-F15) that will never change. See Frozen Foundations.

## G

### Governance Tier
Either STANDARD (dial \< 2/3) or ELEVATED (dial &ge; 2/3). Determines which governance checks apply.

## H

### Hash Access
The set of hash levels a session can use for pattern matching. Determined by dial zone: REPLAY gets L0 only, CREATE gets L0-L3. Encoded in the SCT.

### Hash Level
One of 4 levels of content-addressed hashing: L0 (Exact), L1 (Structural), L2 (Flow), L3 (Intent). Each level strips more detail, enabling privacy-preserving sharing. See Hash Levels.

### HITL (Human-in-the-Loop)
Check 10 in the governance pipeline. Required for PUT and CALL effects in the [ELEVATED tier](#elevated-tier) (dial &ge; 2/3). Blocks execution until a human approves or denies. Managed via `spl hitl pending/approve/deny`.

## L

### Latency
Round-trip time in milliseconds for a proxied API call. Recorded in each response record.

### Lineage
The cryptographic chain linking derived work to its source materials. Every output references the content hashes of its inputs, creating an immutable attribution graph.

## M

### Model
The LLM model used for a call (e.g., claude-sonnet-4-6, gpt-4o). Recorded in proxy metadata.

### Monotonic Narrowing
The principle that child namespaces can never have more permissions than their parent. Capabilities compose via set intersection, deny rules via union, budgets via min(). Governance can only get stricter as you go deeper.

## N

### Namespace
The unit of governance, tenancy, federation, secrets, and budgets. Namespaces form a 5-level hierarchy (DEFAULT, ORG, PROJECT, ENV, JOB) where policies monotonically narrow.

## O

### Observation
A record of successful or failed effect execution. Observations update trust scores and are the unit of [federation](#federation) — registries share observation counts at L1-L3 hash levels.

### Operation
A specialization of a primitive: `db.query` is a GET operation, `llm.generate` is a CALL operation. Defaults to the lowercase primitive if not specified. Matched via glob patterns in policies.

## P

### Proxy
See [API Proxy](#api-proxy).

### Pattern
A reusable computation template stored in the registry, identified by content-addressed hashes at 4 levels. Patterns are discovered through observation and can be matched at varying granularity via the dial.

### Principal
An entity with identity: a user, service account, runner, or anonymous actor. Every governance decision traces back to a principal via their DID.

### Primitive
One of the 4 frozen effect types: GET (read), PUT (write), CALL (invoke), MAP (transform). See The Effect Algebra.

## R

### Record
A single unit of evidence. Every API call through the proxy produces records with metadata (model, tokens, cost, latency).

### Registry
The governance engine: computes SCTs, manages policies, stores observations, coordinates federation, maintains audit trails. Runs locally via `spl serve` or in production.

## S

### SCT (Session Capability Token)
Session permissions token — computed automatically at session start. Encodes what you can do and how much budget you have.

### Service Account
A machine identity with a DID, API key, and configured maximum dial. Managed via `spl auth sa-create/sa-list/sa-revoke/sa-rotate`.

### Shape
One of the 5 frozen data types: VOID, ONE, OPTIONAL, MANY, KEYED. Every effect has an input shape and output shape. See The Effect Algebra.

### spl
The Syncropel CLI command. See [CLI Reference](/docs/reference/cli).

## T

### Thread
A group of related records. When you make API calls for a task, the related records are grouped into a thread.

### Tokens
The number of input and output tokens in an API call, as reported by the LLM provider. Used for cost estimation.

### Trace
The complete record of an execution: all effects, their inputs, outputs, and timing. Traces are the primary output of execution — inspectable via `spl trace ls/show/stats`.

### Trust Score
A confidence measure computed from your track record. Accounts for both success rate and sample size, combined with default starting trust and temporal decay, and bridges to the dial ceiling. See Trust.
