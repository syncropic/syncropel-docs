---
title: Glossary
description: Plain-language definitions of the terms used across Syncropel.
---

## A

**Actor**
Any participant that creates records — a person, an AI agent, a service account, or a system component. Identified by a DID. See [Actors](/docs/concepts/actors).

**Act Type**
One of 8 types that classify what a record represents: `INTEND`, `DO`, `KNOW`, `LEARN` (coordination) and `GET`, `PUT`, `CALL`, `MAP` (effects). See [Records](/docs/concepts/records).

**Adapter**
The connection between Syncropel and something that does work for it. A command-line adapter runs a program on your machine (an agent such as Claude Code, Codex CLI, or OpenCode, plus `bash` and your own programs). A web adapter calls an AI provider such as Anthropic or OpenAI over HTTP. Once an actor is linked to an adapter, work sent to that actor goes through it.

**AITL (Actor-in-the-Loop)**
An older name for the **decision gate**. See below.

**Approval**
A `KNOW` record with `body.verdict: "accept"` from an independent evaluator. Creates trust evidence. See [Trust](/docs/concepts/trust).

## B

**Bearer Token**
A secret string that proves who you are when a program calls the HTTP API. Create one with `spl service-account create` and send it in the `Authorization: Bearer <token>` header. The workspace then treats the request as coming from that service account. See [Keyring](/docs/operate/keyring).

**Body**
The free-form JSON content of a record (`record.body`). See [Record Format](/docs/reference/record-format).

**Body Kind**
A label in `body.kind` that says what type of content a record carries, written as `scope.category.entity[.version]`. See [`body.kind` manifest](/docs/guides/body-kind-manifest).

**Broadcast**
How your workspace tells everything that is listening (live views, automations, paired workspaces) that a new record arrived. Settings changes also take effect this way, which is why they need no restart.

## C

**Canonical JSON**
A fixed way of writing JSON (keys in alphabetical order, no extra spaces) so that the same content always produces the same bytes. It is used to compute a record's ID. See [Record Format — canonical JSON](/docs/reference/record-format#canonical-json-encoding).

**CEL (Common Expression Language)**
The small expression language you use to write conditions for triggers, routing, preconditions, status rules, health checks, decision policies, and permissions. See [CEL expressions](/docs/guides/cel-expressions).

**Clock**
A counter on each record that goes up for each actor on each thread. It starts at 0 and puts records in order within a thread. It is not a wall-clock time.

**Consent Grant**
A `LEARN` record on the `th_consent` thread that authorizes records to cross a namespace boundary during federation. Specifies `source_namespace`, `target_namespace`, and allowed hash levels (L0–L3). Default is strict: no grant, no crossing.

**Coordinator (Fleet)**
The instance in a fleet that tracks which instances are running and hands out work to the others. Any instance can take this role through settings.

**Correction**
A `KNOW` record with `body.topic: "correction"` that points to an earlier record that was wrong. Readers use the later record's content. The wrong record stays in history.

**Scheduled maintenance**
Work your workspace does on a schedule in the background: lowering old trust scores, promoting reliable patterns, saving snapshots, and writing cost reports. See [The Engine](/docs/concepts/engine#running-scheduled-work).

**Crystallization**
When a pattern has proven reliable enough to run automatically. It must meet four tests: trust of at least 0.90, at least 100 observations, a real saving from reusing it, and success from more than one source. See [Patterns](/docs/concepts/patterns#when-a-pattern-becomes-permanent).

**Drift alert**
A warning that an actor's success rate has changed meaningfully. See current alerts at `GET /v1/governance/cusum-alerts`.

## D

**Decision gate**
How your workspace asks someone to decide before it goes on. The request can come from the assistant, a paused task, a `spl decompose` plan, or a paired workspace. If the assistant is at least 0.90 confident, the change applies by itself. At 0.60 or above, it asks a person. Below that, it is logged and dropped. See requests with `spl decisions list` (they also appear under NEEDS in `spl resume`) and answer them with `spl decisions approve`, `reject`, `choose`, `provide`, or `ack`. You can pick an option, provide a value, or acknowledge. See [Your first decision gate](/docs/tutorials/your-first-decision).

**DID (Decentralized Identifier)**
An actor's permanent identity. Three kinds work: `did:key`, `did:web`, and `did:sync`. Names inside your workspace look like `did:sync:user:…`, `did:sync:agent:…`, and `did:sync:system:…`.

**Dial**
A continuous value in `[0, 1]` that maps trust and pattern match strength to cost zones. Zones: REPLAY (0.00–0.33), ADAPT (0.33–0.50), EXPLORE (0.50–0.67), CREATE (0.67–1.00). See [Trust — the dial](/docs/concepts/trust).

**Dispatch**
Sending work to an actor to carry out. `spl task dispatch` starts a thread for the work, records the request, and hands it to the actor through its adapter. See [Routing rules](/docs/guides/routing-rules).

**Domain**
A kind of work, such as `code`, `ops`, `data`, `research`, `shell`, `api`, `spec`, `agent`, `meta`, `browser`, or `workflow`. Trust is tracked per domain, so an actor can be trusted for one and not another. You choose the domain when you create a record; the list is not fixed.

## E

**Engine**
The part of your workspace that does the background work. It stores each new record and announces it, sends work to the right actor, updates trust and watches for stalled work, and runs scheduled maintenance. You rarely deal with it directly. See [The Engine](/docs/concepts/engine).

**Evaluation Gate**
The requirement that completed work be reviewed by an independent evaluator (a different DID than the completer) before trust evidence is created. Structurally enforced — self-verdicts produce no trust. See [Trust — independence](/docs/concepts/trust).

**Event Trigger**
A setting that starts an actor when a matching record appears or at a scheduled time. It has a cooldown and loop protection so it cannot fire endlessly. See [Scheduled triggers](/docs/guides/scheduled-triggers).

## F

**Faculty**
Something that does a kind of work, named for what it does rather than what it is made of. A language model, a solver, a classifier, an outside service, or a script can all be a Faculty. Each takes in work and returns a result record, is judged by an independent reviewer, and earns trust from those verdicts. Deploy one with `spl faculty deploy`. See [Faculties](/docs/concepts/faculty).

**Fan-out**
Splitting one piece of work into several sub-tasks. The parent request lists the sub-tasks (`body.subtasks`) and a rule for when it is done (`body.join`). Each sub-task goes to a worker instance, and the parent closes when the rule is met.

**Federation**
How two or more Syncropel instances share records while keeping trust boundaries intact. Pull-based, signed, consent-filtered. See [Federation](/docs/concepts/federation).

**Fleet**
Two or more `spl` instances working together. One is the coordinator and the others are workers. Any instance can take either role.

**Freeze and stop switches**
The list of active freeze and emergency-stop switches. It is checked on every write to decide whether a record is allowed.

**Fold**
Working out the current state of a thread by reading its records in order. Task status, trust, and settings all come from this, so there is no separate place where state can drift out of date.

**Status Rule**
A CEL expression, saved as a settings record, that changes how a task or thread status is worked out. Use it for status changes specific to your workspace. See [CEL — fold_rule context](/docs/guides/cel-expressions).

## G

**Governance**
The union of namespaces, permission rules, CEL policies, consent grants, kill switch, and audit export. Syncropel's mechanism for enforcing "who can do what where". See [Namespaces](/docs/concepts/namespaces) and [SIEM integration](/docs/guides/siem-integration).

## H

**Hash Levels (L0 / L1 / L2 / L3)**
Four hash-signature levels of a record, each throwing away more detail. L0 is exact content. L1 is structural (`dial + in + op + out + p`). L2 is flow (`in + out + p`). L3 is intent (`in + out`). L0 never crosses a namespace without consent; L1–L3 can. Containment: `L0 ⟹ L1 ⟹ L2 ⟹ L3`. See [Patterns](/docs/concepts/patterns).

**Heartbeat**
A regular check-in from each running instance (every 15 seconds by default) with its address, version, uptime, active work, and health. The coordinator uses the latest check-in to show each instance as live, stale, or archived.

## I

**Receiving records**
When a record arrives, your workspace checks it, saves it, and announces it right away. It never waits for follow-on work to finish.

**Instance**
A single `spl serve` instance with its own `SYNCROPEL_HOME`, record database, port, and identity. An instance may run standalone or as a coordinator/worker in a fleet.

**Instance Registry**
The coordinator's list of which instances are running.

**Intelligence**
Syncropel's own assistant, `did:sync:system:intelligence`. It acts when no routing rule matches, and proposes a rule through the decision gate rather than acting directly. Accepted proposals raise its meta-trust.

## J

**Join Predicate**
The CEL condition in a fan-out parent's `body.join` that says when the parent closes. Shapes: `all` (every child), `any` (first accept), `k_of_n` (K accepts), or custom CEL. `all` and custom CEL cannot close early if only some children have reported.

**Judged By**
The 8th record field. It points to the record being judged. It is not part of the record ID. Trust uses it, and the same observation with a different `judged_by` is a second reviewer's separate view.

## K

**Kill Switch**
A reversible freeze with three levels. **Soft** blocks new INTEND/DO/CALL records in a namespace while KNOW/LEARN can still finish. **Hard** also refuses all records after a grace period. **Emergency** sets the dial to 0 (REPLAY only) in every namespace. A later record reverses each level.

## L

**LEARN**
One of 4 coordination act types. Records an insight or persistent decision — a configuration change, a lesson learned, a new rule. Config records (routing rules, triggers, CEL policies, auth toggle) are LEARN records on `th_engine_config`.

**Logical Clock**
See **Clock**.

## M

**Marketplace (Calibrated)**
Sends each piece of work to the most trusted [Faculty](/docs/concepts/faculty) that says it can do it, judged only by earned trust in that domain. A minimum bar keeps unproven candidates from displacing proven ones, and ties favor the current choice. See [The Calibrated Marketplace](/docs/concepts/marketplace).

**Memory**
What an actor remembers between sessions: preferences, corrections, project state, and references. It is saved as `LEARN` records and loaded when work is sent to the actor. See [Actors — memory](/docs/concepts/actors#memory-persistent-context-across-sessions).

**Meta-Trust**
The trust score of Syncropel's assistant itself, kept apart from any one domain. It rises when its proposals are accepted and falls when they are rejected.

**Narrowing rule**
A child namespace can never have more permissions than its parent. A record in a child namespace is refused if any parent is missing or not active. See [Namespaces — narrowing](/docs/concepts/namespaces#the-narrowing-rule).

## N

**Namespace**
A scope that groups records by organization, project, environment, or job. Every record belongs to exactly one namespace (`body.namespace`, or `default` if not set). Five levels: `DEFAULT → ORG → PROJECT → ENV → JOB`. See [Namespaces](/docs/concepts/namespaces).

**Namespace Registry**
The list of namespaces you have declared. It updates as soon as you add one.

## P

**Pair (Federation)**
A lasting link that says "this workspace pulls changes for this thread from that peer." It has `peer_did`, `peer_url`, `thread_id`, and `cursor` (how far it has read). Create one with `POST /v1/federation/sync/pairs` or `spl fleet sync add`. See [Federation](/docs/concepts/federation#pairs-how-workspaces-connect).

**Participant**
Any actor who has written a record on a thread. `spl thread show` lists participants with their roles.

**Pattern**
A repeated shape of successful work, matched at several levels of detail (L1 exact through L3 intent). A pattern can crystallize once it meets the four tests. See [Patterns](/docs/concepts/patterns).

**Permission Rule**
A CEL condition checked on every write to allow or deny it. When permissions are enabled, anything not allowed is denied. Saved as a settings record. See [CEL — permission context](/docs/guides/cel-expressions).

**Precondition**
A CEL condition on a task that keeps it from starting until it is true. Once it holds, the task becomes ready. See [Task management](/docs/guides/task-management).

**Proxy Adapter**
An adapter that calls an AI provider over HTTP (Anthropic, OpenAI, Google, Mistral, or your own endpoint) instead of running a program. `/v1/proxy/messages` accepts the Anthropic Messages API format.

## R

**Routing**
When a record arrives, your workspace picks the actor to handle it and sends the work there, or marks the record as handled. Up to 4 pieces of work run at once by default.

**Record**
The basic unit: an immutable item with 8 fields whose ID is computed from its content. Records are never edited or deleted. See [Records](/docs/concepts/records).

**System Threads**
Built-in threads that hold your workspace's own data. You will see these names in settings and API responses: `th_engine_config` (workspace settings), `th_actor_registry` (actors), `th_namespace_registry` (namespaces), `th_instance_registry` (running instances), `th_fleet_control` (freeze and stop switches), and `th_consent` (permission to share across namespaces).

**Routing Rule**
A CEL condition, saved as a settings record with `body.topic: "routing_rule"`, that sends matching records to an actor. Rules are checked in priority order and the first match wins. See [Routing rules](/docs/guides/routing-rules).

## S

**Service Account (SA)**
An account for a program rather than a person, with a DID of the form `did:sync:system:sa_…`. Create one with `spl service-account create`. It signs in with a bearer token and is limited to the namespaces and permissions you give it. See [Keyring](/docs/operate/keyring).

**SSE (Server-Sent Events)**
A way for the server to stream updates to you over one HTTP connection. Syncropel uses it for streamed model replies (`/v1/proxy/messages` with `stream=true`) and for MCP (`/v1/mcp/sse`).

**Snapshot**
A `.snap.jsonl` file holding a thread's records and a checklist that detects tampering. Use it for backup, moving a workspace, or starting a fleet. Restoring it twice does not create duplicates. See [Backup and restore](/docs/guides/backup-restore).

**Substrate**
The shared, append-only record of everything that happens, which every actor reads from and writes to. An actor's DID stays the same; what powers it (the AI model, adapter, or tool) can change.

## T

**Task**
A thread whose first `INTEND` record has `body.task = true` and an alias, assignee, domain, and priority. Its status is worked out from its records. Manage tasks with `spl task`. See [Task management](/docs/guides/task-management).

**Thread**
A sequence of records sharing a thread ID. Represents a workflow, task, conversation, or any coordinated activity. See [Threads](/docs/concepts/threads).

**Trust updates**
Once a minute by default, your workspace updates trust scores, checks for drift, and flags stalled work.

**Trust**
A score built from evidence such as approved work and reviewed outcomes. It is tracked per `(actor, domain, judged_by)`, uses the 95% Wilson lower bound, and decays with a 90-day half-life. See [Trust](/docs/concepts/trust).

## W

**Wilson Lower Bound**
A cautious estimate of a success rate at 95% confidence. With few observations it stays low, and with many it approaches the real rate. It is the trust score.

**Worker (Fleet)**
An instance that runs dispatched work and checks in with the coordinator. A fleet can have many workers.

## Z

**Zone**
One of four cost levels on the dial: REPLAY (near zero), ADAPT (low), EXPLORE (moderate), CREATE (full).
