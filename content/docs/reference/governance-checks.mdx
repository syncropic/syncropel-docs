## Overview

Every action in Syncropel passes through 10 governance checks before execution. If any check fails, the action is denied.

| # | Check | What It Validates |
|---|-------|-------------------|
| 1 | Revocation | Session hasn't been revoked |
| 2 | Policy Freshness | Policies haven't changed since session started |
| 3 | Capability | Action type is permitted (GET, PUT, CALL, MAP) |
| 4 | Deny Rules | Action isn't explicitly forbidden |
| 5 | Session Budget | Overall budget hasn't been exceeded |
| 6 | Trust Level | Trust score permits this autonomy level |
| 7 | Hash Access | Hash level access is permitted |
| 8 | Per-Action Budget | This specific action fits within limits |
| 9 | Structural | Action is well-formed and valid |
| 10 | Human Approval | Action has required human sign-off (if needed) |

## Denial Reasons

When a check fails, you'll see a clear error message indicating which check failed and why. Common reasons:

- **Budget exceeded** — your session has used its allocated budget
- **Capability denied** — you don't have permission for this action type in this namespace
- **Trust too low** — your trust score doesn't permit this level of autonomy
