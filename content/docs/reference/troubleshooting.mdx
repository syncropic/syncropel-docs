## Binary not found after install

**Symptom:** `spl: command not found` after running the install script.

**Cause:** `~/.local/bin` is not in your PATH.

**Fix:**

```bash
export PATH="$HOME/.local/bin:$PATH"
# Make it permanent:
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

## Python version too old

**Symptom:** Install fails with "Python 3.12+ required" or import errors.

**Cause:** System Python is 3.10 or 3.11 (common on Ubuntu 22.04).

**Fix:**

```bash
# macOS
brew install python@3.12

# Ubuntu/Debian
sudo apt install python3.12

# Or let uv manage Python:
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.12
```

## Port 9100 already in use

**Symptom:** `spl serve` fails with "address already in use".

**Cause:** Another `spl serve` instance or another process is using port 9100.

**Fix:**

```bash
# Find what's using port 9100
lsof -i :9100

# Kill existing spl serve
spl serve --stop

# Or use a different port
spl serve --port 9200
```

## Proxy returns 502

**Symptom:** API calls through the proxy return `502 Bad Gateway`.

**Cause:** The proxy can't reach the upstream API (Anthropic/OpenAI).

**Fix:**

```bash
# Check your API key is set
cat ~/.syncro/secrets/anthropic_key | head -c 20

# Check internet connectivity
curl -I https://api.anthropic.com

# Set API key if missing
spl config set-key
```

## Database locked

**Symptom:** Errors about "database is locked" or "IO error".

**Cause:** Multiple `spl serve` instances or unclean shutdown.

**Fix:**

```bash
# Stop all instances
spl serve --stop
pkill -f "spl serve"

# Remove stale lock files
rm -f ~/.syncro/hub.db.wal

# Restart
spl serve
```

## Database corrupted

**Symptom:** Startup crashes with DuckDB errors.

**Cause:** Unclean shutdown corrupted the database file.

**Fix:**

```bash
# Back up the corrupted file
mv ~/.syncro/hub.db ~/.syncro/hub.db.corrupted

# Start fresh
spl serve
```

## LLM calls not appearing in console

**Symptom:** You're making API calls but they don't show in the console.

**Cause:** Your SDK isn't pointing at the proxy, or the base URL format is wrong.

**Fix:**

```python
# Correct — Anthropic
client = anthropic.Client(base_url="http://localhost:9100")

# Correct — OpenAI
client = OpenAI(base_url="http://localhost:9100/v1")

# Wrong — don't include /v1 for Anthropic
# client = anthropic.Client(base_url="http://localhost:9100/v1")  # WRONG
```

Check that `spl serve` is actually running:

```bash
curl -s http://localhost:9100/health | python3 -m json.tool
```

## Rate limited (429)

**Symptom:** API calls return `429 Too Many Requests`.

**Cause:** The proxy rate limits to 120 requests/minute per client.

**Fix:** Wait 1 second and retry. The `Retry-After` header tells you when to retry. If you need higher limits, this is a daemon setting (not yet configurable).

## Claude Code hooks not firing

**Symptom:** Claude Code sessions aren't being recorded.

**Cause:** `spl setup --claude` hasn't been run, or hooks weren't installed correctly.

**Fix:**

```bash
# Reinstall hooks
spl setup --claude

# Verify
cat ~/.claude/settings.json | python3 -m json.tool | grep syncropel
```

## API key not accepted

**Symptom:** Proxy returns authentication errors from upstream API.

**Cause:** API key format is wrong or key is expired/invalid.

**Fix:**

```bash
# Reconfigure the key
spl config set-key

# The key should start with sk-ant- (Anthropic) or sk- (OpenAI)
```

## Init wizard hangs

**Symptom:** `spl init` waits for input and never finishes.

**Cause:** Running in a non-interactive environment (Docker, CI, script).

**Fix:**

```bash
# Use non-interactive mode
spl init --yes

# With a specific API key
spl init --key "$API_KEY" --yes
```

## Still stuck?

Check the daemon logs:

```bash
spl serve --logs
```

Or start the registry in foreground mode to see all output:

```bash
spl serve
```
