Syncropel's Generative Trace Model (GTM) treats computation as **autoregressive effect generation** — similar to how language models generate tokens, the GTM generates effects. These 12 effect kinds form a Turing-complete minimum vocabulary.

## The 12 Effect Kinds

| Kind | Symbol | Description |
|------|--------|-------------|
| **READ** | `→` | Load data from a source |
| **WRITE** | `←` | Persist data to a destination |
| **TRANSFORM** | `⟲` | Apply a pure transformation to data |
| **CALL** | `☎` | Invoke an external service or function |
| **SEQUENCE** | `→→` | Execute effects in order |
| **PARALLEL** | `⇉` | Execute effects concurrently |
| **BRANCH** | `⑂` | Conditional execution based on a predicate |
| **LOOP** | `↻` | Repeated execution with a termination condition |
| **INVOKE** | `▶` | Execute a sub-trace (composition) |
| **COMPOSE** | `◆` | Combine multiple traces into one |
| **OBSERVE** | `👁` | Emit an observable event (logging, metrics, telemetry) |
| **HALT** | `⏹` | Terminate execution with a result |

## Effect Structure

Every effect has five components:

```
Effect = Kind × Shape × Operation × Capability × Parameters
```

- **Kind**: One of the 12 types above (frozen — will not change)
- **Shape**: The data flow pattern (e.g., "one-to-many", "aggregation")
- **Operation**: The specific operation within the kind (e.g., `sql.query`, `http.get`)
- **Capability**: The system capability required (e.g., `database`, `network`)
- **Parameters**: Runtime values (e.g., query string, URL, filter conditions)

## Abstraction Levels

Effects can be described at four levels of abstraction, enabling pattern matching at different granularities:

| Level | Contains | Use |
|-------|----------|-----|
| **Level 3: Intent** | Shape flow only | Highest transfer — matches across domains |
| **Level 2: Flow** | + Effect kinds | Structural matching — same kind of operations |
| **Level 1: Structural** | + Operations | Operational matching — same specific operations |
| **Level 0: Exact** | + Parameters | Perfect replay — exact reproduction |

The [Dial](/docs/concepts/the-dial) controls which level the system matches at: low Dial values match at Level 0 (exact), high Dial values generate from Level 3 (intent).

## Example Trace

A simple data analysis trace might contain:

```
READ    → Load customer data from SQL database
READ    → Load support tickets from API
TRANSFORM → Join datasets on customer_id
TRANSFORM → Calculate purchase frequency
TRANSFORM → Calculate ticket sentiment scores
BRANCH  → If frequency < threshold AND sentiment < threshold
  WRITE → Flag as at-risk customer
OBSERVE → Emit metrics (customers_analyzed, flagged_count)
HALT    → Return results
```
