## What is Code Mode

Code Mode is the pattern where an AI agent accomplishes a task by **writing a short program** using a typed SDK, and running that program in a sandbox. The program does the work — multiple emits, queries, transformations. Only the final result flows back to the agent's context.

It contrasts with **Traditional MCP**, where the agent calls each tool one at a time and each result flows through the model:

- **Traditional MCP**: 10 tool calls = 10 context round-trips = 10× token cost
- **Code Mode**: 10 SDK calls inside one sandbox run = 1 context round-trip = 1× token cost

[Anthropic](https://www.anthropic.com/engineering/code-execution-with-mcp) reports 98.7% token savings for multi-step MCP workflows when switching to Code Mode. [Cloudflare](https://blog.cloudflare.com/code-mode-mcp/) reduced a 2,500-endpoint API to 2 Code Mode tools with equivalent functionality.

## Why Syncropel's SDKs are already Code Mode surfaces

We didn't build a separate "Code Mode layer." The SDKs we've been shipping since v0.15 (`@syncropel/sdk` on npm, `syncropel` on PyPI) are exactly the shape Anthropic and Cloudflare advocate: typed code APIs organized in a filesystem, with stable contracts and graceful transport failure.

```
sdks/typescript/src/
├── client.ts          ← emit, query, queryThread, intend, fulfill
├── refs.ts            ← 11 Ref.* canonical constructors
├── grammar.ts         ← body.kind validator
├── identity.ts        ← DID handling
└── canonical.ts       ← deterministic JSON
```

When an agent runs `code_execution`, you just give it the SDK. It writes TypeScript, the sandbox runs it, the SDK handles the wire protocol.

## Prerequisites

You need an agent harness that supports code execution. Common options:

- **Claude with `code_execution`** (via Anthropic API's built-in code tool)
- **Cloudflare Workers** running an agent loop with fetch + V8 isolates
- **Custom Python/Node sandbox** you control (Docker, Firecracker, gvisor)
- **OpenAI Code Interpreter** (supports Python; use the `syncropel` PyPI package)

And a Syncropel daemon reachable from the sandbox's network:

- Local: `http://localhost:9100` if the sandbox runs on the same machine
- Remote: `https://your-host.example.com:9100` with a bearer token
- Hosted: `https://syncropel.com/api/<your-did>` (v0.19+, deferred)

## Quickstart — Python, Claude code_execution

The most common combination: Anthropic's Claude with `code_execution` tool, using the `syncropel` PyPI package.

### 1. Install in your agent's Python sandbox

Typically handled via the sandbox's package manager or a pre-warmed environment:

```bash
pip install syncropel anthropic
```

### 2. The agent writes this (or you give it a starter template)

```python
import os
from syncropel import Client, Identity, Ref

client = Client(
    endpoint=os.environ.get("SYNCROPEL_URL", "http://localhost:9100"),
    identity=Identity.static(os.environ.get("AGENT_DID", "did:example:agent")),
    api_key=os.environ.get("SPL_TOKEN"),
)

# Start a thread
intend = client.intend("Investigate auth bug #342", thread_prefix="bug-342")
thread = intend.thread

# Do the work — each step is a record
for step in [
    "Read the auth module source",
    "Identified the token-refresh race condition",
    "Wrote a failing test for the race",
    "Applied fix: wrap refresh in mutex",
    "Test now passes",
]:
    client.do(step, thread=thread)

# Observe + learn
client.know(
    f"Fix committed. Root cause was lock-free optimistic refresh retry loop.",
    thread=thread,
)
client.learn(
    "Token refresh in concurrent contexts must be mutexed",
    thread=thread,
)

# Return summary to the agent's context
records = client.query_thread(thread)
print(f"Bug #342 investigation complete — {len(records)} records in thread {thread}")
print(f"Trust events recorded for did:sync:agent:auth-reviewer")
```

The agent's context sees the final `print()` output (2 lines) instead of 5-7 tool calls worth of chatter.

### 3. Claude returns the summary + reasoning

```
I investigated bug #342 and found the root cause: the auth module's
token refresh logic had a race condition in concurrent refresh attempts.
I applied a mutex around the refresh path, wrote a failing test first,
verified it passes, and recorded 8 records in thread bug-342.
```

Efficient, auditable, and the user can `spl thread records bug-342` to see exactly what the agent did.

## Quickstart — TypeScript, Cloudflare Workers

```typescript
import { Client, Identity } from "@syncropel/sdk";

interface Env {
  SYNCROPEL_URL: string;
  SPL_TOKEN: string;
  AGENT_DID: string;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const client = new Client({
      endpoint: env.SYNCROPEL_URL,
      identity: Identity.static(env.AGENT_DID),
      apiKey: env.SPL_TOKEN,
    });

    // Start a thread
    const intent = await client.intend({
      goal: "Process incoming webhook",
      thread: "th_webhooks",
    });

    // Coordinated work — zero model round-trips between these
    await client.do({
      body: { event: request.headers.get("x-event"), path: new URL(request.url).pathname },
      thread: "th_webhooks",
    });

    // Process the webhook content (your actual business logic here)
    const result = await processWebhook(request);

    // Record the outcome
    await client.know({
      body: { status: "processed", result_code: result.code },
      thread: "th_webhooks",
    });

    return new Response(JSON.stringify({ ok: true }), {
      headers: { "content-type": "application/json" },
    });
  },
};

async function processWebhook(request: Request) {
  // Business logic — not Syncropel's concern
  return { code: "ok" };
}
```

Deploy with `wrangler deploy`. Every webhook handled emits 3 records. Zero LLM context round-trips per webhook.

## Design patterns

### Pattern: long-running agent with session checkpoints

For agents that run for hours or days, use session checkpoints to persist progress:

```python
# Save at end of each work session
result = client.emit(
    act="LEARN",
    kind="agent.session.checkpoint",
    body={
        "summary": "Completed auth refactor; next: migration tests",
        "learnings": ["mutex pattern worked", "refactor touched 14 files"],
        "next_steps": "Write migration tests",
    },
    thread=session_thread,
)
```

The next session resumes by reading the latest checkpoint on the thread. No context-window-of-history required.

### Pattern: fan-out with independent verification

When the agent delegates subtasks to other agents:

```python
# Parent agent creates subtasks
for worker in ["agent-a", "agent-b", "agent-c"]:
    child = client.intend(
        f"Review module X for {worker}",
        thread_prefix=f"review-{worker}",
    )
    # Each worker independently emits its records
    # Parent polls or subscribes for completion
```

Uses Syncropel's [fleet + fan-out primitives](/docs/tutorials/first-fanout) under the hood.

### Pattern: trust-aware dispatch

Before choosing an approach, the agent reads trust:

```python
coding_trust = client.get_trust("did:sync:agent:me", "code")
if coding_trust.wilson_lb < 0.5:
    # Low confidence — emit an INTEND with `body.awaits: "actor_decision"`
    # for human review before proceeding
    pass
else:
    # High confidence — proceed + emit DO records
    pass
```

## Error handling

The SDK is **fail-open** on transport errors. Every emit returns an `EmitResult`:

```python
result = client.emit(...)
if not result.success:
    # Transport error — log locally, retry later, but don't crash
    print(f"Syncropel unreachable: {result.error}")
```

This is intentional: your agent's core work shouldn't crash because a coordination record failed to reach the daemon. The alternative (throwing exceptions) makes Syncropel a liability instead of an asset.

Grammar errors (malformed `body.kind`, invalid `act`) DO raise — those are programmer errors worth catching.

## Authentication

Same as everywhere:

```python
client = Client(
    endpoint="https://your-host.example.com:9100",
    identity=Identity.static("did:sync:agent:me"),
    api_key=os.environ["SPL_TOKEN"],  # from ~/.syncro/token or env
)
```

For unauthenticated local daemons (dev mode), omit `api_key`.

For cloud agents, store the token in your platform's secret manager:
- **Cloudflare Workers**: `wrangler secret put SPL_TOKEN`
- **AWS Lambda**: AWS Secrets Manager
- **Anthropic API**: encrypted user metadata

See [Authentication & Service Accounts](/docs/operate/keyring) for how to mint a scoped token.

## When Code Mode is the wrong choice

- **You want a record of what the agent did without writing code** → [Pattern 1 (MCP)](/docs/integrate/ai-clients#pattern-1--traditional-mcp-stdio) — simpler setup
- **You don't control the agent's runtime (consumer AI client)** → Pattern 1 or 2
- **You want the agent to see tool results in-context** (e.g., "what did the query return?") → Traditional MCP lets the agent reason over each result; Code Mode is better when the code handles results itself
- **You only emit 1-2 records per session** → Code Mode's overhead isn't worth it
